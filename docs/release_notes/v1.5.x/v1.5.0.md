## [1.5.0] - TBD - Trust and Evidence Integrity (Draft)

## Overview

v1.5.0 readiness work is in progress. These draft notes describe implemented changes; the release gate is not complete.

## Security

- The generic document and settings HTTP API no longer writes directly to the Gateway document store. Previously, app and outbound Operator certificates could overwrite or delete trust-bearing records, including signer keys, certificate revocations, users, and settings, through `/api/v1/data/*`. Regression coverage reproduces those writes on the previous implementation and verifies their rejection without stored changes after removal.

- Delegated app certificates no longer authenticate as their approving user on owner-only routes. The delegated user SAN remains available for governed envelope attribution, L3 suspensions, observe producers, inference, and Tribunal requests. Fully enrolled apps are denied signer registration and app revocation through the admin endpoints in every posture.

- App and outbound Operator certificates now have explicit method-and-route allowlists. Unlisted pairs fail with HTTP 403 before reaching a handler. Supported app ingress, Tribunal requests, and permitted reads remain available; outbound Operators retain session validation and their outbound pub/sub transport.

- Local reports and KSI signature checks use explicitly supplied trust anchors instead of decoding a public key from the evidence's own signer ID. Reports verify receipt signatures, persistence attestations, and commitment-stage linkage. Unknown keys fail verification; receipts that pass KSI verification include verifier identity, version, verification time, and a content digest. These checks detect evidence tampering against the supplied anchors; they do not protect against compromise of the host and its signing-key keystore.

## Protocol / Changed

- The generic data handlers reject write methods with HTTP 405. Workload identity allowlists can reject a request earlier with HTTP 403. Permitted document and settings `GET` endpoints and read-only `POST /api/v1/data/{collection}/_query` remain available.

- Operator enrollment binds an Ed25519 auditor public key and matching key ID alongside the actuator key, including the auditor-key fingerprint in the enrollment transcript. The local auditor public key is exported as `pki/Auditor_pub.json` under the runtime root, alongside `pki/Actuator_pub.json`. Auditor and actuator lookup remain separate trust roles.

- `ZTD_TEST_REEXEC` is a registered test-harness environment key. Unregistered `ZTD_TEST_*` keys no longer bypass registry checks. Listener-capable re-exec helpers are reached only from integration-tagged test entry points.

## Performance

- Evaluation Explorer bootstrap ingestion reuses parsed payloads, defers source-record serialization, decodes campaign envelopes once, and avoids copying the growing campaign context for each assignment. Validation and malformed-record rollback remain enforced.
- Small browser bootstrap snapshots use `localStorage`; snapshots above 250 projections use IndexedDB structured clone. Large writes and quota failures remove stale synchronous-cache data. Startup installs the snapshot and opens SSE before saving the new cache.
- The public mirror caches serialized JSON and gzip bootstrap responses, invalidates them for source freshness and proof-summary changes, and handles conditional requests before writing compressed bytes. Response decoding and encoding run outside the mirror mutation lock after a coherent snapshot capture.

## Upgrade

Remove calls that write through the generic data API before upgrading the Gateway. Application record changes use classified governed actions. Platform authority changes use the corresponding enrollment and management workflows; submitting an arbitrary document envelope does not grant authority over trust-bearing collections.

Upgrade the Gateway and outbound Operators together for the auditor-key enrollment contract. Existing Operator documents without auditor bindings cannot supply enrolled auditor trust; use governed enrollment to establish those bindings and preserve runtime signing keys and authoritative audit stores.

Mirror startup rejects missing or invalid current-state snapshot markers rather than backfilling an old schema. Follow the [mirror rebuild procedure](../../architecture/public_spectator.md#upgrade-and-verification) for the disposable mirror store; preserve canonical evaluation evidence and publisher state.

These changes remove HTTP contracts and change enrollment contracts, so they belong to the v1.5 minor release. Other trust-store routes, signed checkpoints, transport enforcement, and full release qualification remain open.

## Qualification

Release qualification is pending. The targeted data API regression uses real Gateway TLS, local PKI, and SQLite with app, owner-delegated app, enrolled outbound Operator, and owner CLI identities. App policies and certificates are seeded through fixture services; this test does not qualify the complete owner-approved app enrollment flow or the remaining signer/admin write routes.
