## [1.5.0] - 2026-10-28 - Trust and Evidence Integrity

## Overview

v1.5.0 is a minor release. It removes the ungoverned writes that the generic document and settings API accepted, restricts app and outbound Operator certificates to explicit route allowlists, binds an auditor key at Operator enrollment, signs audit-chain checkpoints, pins one judge per evaluation campaign, and adds `ztd consensus unbind`. The Gateway refreshes L2 trust policy on connected Operators through bootstrap and certificate renewal.

The release also carries the llama.cpp inference provider and model store, sovereign formation roles that accept local providers, and provider-aware eval model maintenance. These were drafted as v1.4.2, which was never tagged, and are folded into this release.

v1.5.0 breaks CLI, wire, and evidence contracts and requires the Gateway and every Operator to upgrade together. See [Compatibility](#compatibility) before upgrading.

## Added

- llama.cpp `llama-server` inference provider for Inference Operators and the Gateway embedded Operator. New flags on `ztd operator start`, `ztd operator deploy`, and `ztd gw start`: `--inference-llamacpp-endpoint` (selects the llama.cpp provider instead of Ollama) and `--inference-llamacpp-model-root` (the llama-server `--models-dir` as seen by the Operator; required with the endpoint). Ollama remains the default provider, and the Ollama flags and defaults are unchanged.
- llama.cpp model store for the Provenance capability: `--model-storage-format ollama|llamacpp` selects the layout under `--model-storage-root`. The default is `ollama`. Setting both an Ollama endpoint and a llama.cpp endpoint fails when inference is enabled. With llama.cpp, `--inference-keep-alive` accepts `-1` or `0`.
- Provider-aware eval model maintenance: `ztd eval models pull` requires an Inference Operator that serves Ollama and fails with `inference: Ollama model pull requires an Inference Operator serving Ollama` otherwise. Model inventory, residency, release, and freeze work with either provider. Sovereign formation roles accept provider class `ollama` or `llamacpp`; delegated formation roles still cannot declare a local provider class.
- Judge pinning for evaluation campaigns. `EvaluationCampaignSpec.judge_variant` freezes one judge that scores every judged criterion, so a scored model no longer grades its own answers. `ztd eval campaigns create --judge <served tag>` selects it from the model registry (default `gemma4:e4b`). Verification rejects any grade attributed to another variant. See `INV-EVAL-CAMP-42` in [Evaluations](../../architecture/evals.md).
- Per-criterion judged content. `ScenarioContentCheck.JudgedCriteria` entries are decided by the pinned judge under rubric `criterion-v1`, with one governed dispatch per criterion, and are sealed in `agent-trace.v10` as `content_judgments`. Each verdict appears as a `content:<criterion id>` semantic grade. The `history-grounding` criterion accepts equivalent wording for empty investigation history. See `INV-EVAL-CAMP-43` through `INV-EVAL-CAMP-45` in [Evaluations](../../architecture/evals.md).
- `ParseInterrogation` and typed `ErrEvaluationInterrogation*` sentinels. One parser now serves both the executor and the grader. A valid Interrogation Protocol reply is graded on the protocol.
- Posture-frozen scenario eligibility: `EvaluationScenarioDefinition.exclude_when_l2_enforced` (proto field 18) is bound into the campaign and catalog digests.
- `HeterogeneousAssignmentTarget.designated_role` (proto field 2).
- `ztd consensus unbind`, backed by the governed action `PLATFORM_ENROLLMENT_UNBIND_CONSENSUS` (`DELETE /api/v1/auth/platform-enrollments/consensus`). Owner-only. Under `ratify` and `notary` the Gateway suspends it for passkey approval (HTTP 202).
- Operator auditor key. Enrollment binds an Ed25519 auditor public key and key ID alongside the actuator key (`OperatorDocument.auditor_public_key` field 38, `auditor_key_id` field 39). The local auditor key is exported as `pki/Auditor_pub.json` under the runtime root, next to `pki/Actuator_pub.json`.
- Signed audit-chain checkpoints (`AuditChainCheckpoint`, `AuditChainCheckpointPayload`). They bind the pruning boundary, checkpoint hash, creation time, format version, and auditor identity.
- Event transport declarations. Every registered event declares its transports in `protocol/constants/events.json`. Pub/sub and SSE publishers reject undeclared transports before publishing.
- Exit code 10 (`ExitCodeActionExecutionFailed`) when a command's governed action was dispatched and approved where required, but failed in execution. Its signed FAILED receipt is the evidence. Every other command error still exits 1.
- `--assignment-timeout` on `ztd eval runs start` and `resume`. It sets an optional per-assignment wall-clock limit; the default `0` adds no deadline.
- `--mirror-origin` on eval and rollout commands, to override the public mirror read origin.
- Eval backup modes: `ztd eval backup --status`, `--compare`, and `--compact`, and `ztd eval restore --verify`. Both take positional snapshot or backup-directory arguments.
- Generated protocol reference docs for the operator, eval, and common protobuf packages under `protocol/docs/reference/api/ztd/`.
- `GovernedDispatchResult.request_envelope` (field 8), and inference and receipt failure codes `RECEIPT_FAILURE_CODE_PROVIDER_STREAM_ERROR` (26), `INFERENCE_DISPATCH_FAILURE_CODE_PROVIDER_STREAM_ERROR` (48), and `INFERENCE_DISPATCH_FAILURE_CODE_REHYDRATION_FAILED` (49).
- Setup scripts for Linux, macOS, and Windows (`scripts/linux-setup.sh`, `scripts/macos-setup.sh`, `scripts/windows-setup.ps1`, with `--build-only` on Windows) and the website installer `website/static/ztd.sh`.
- `ztd operator deploy`, which deploys an Operator to a cloud VM. Live cloud-VM verification is deferred (see [Deferred](#deferred)).
- `make golangci-lint-install`, which installs the pinned golangci-lint, and `ztd test lint --yes`, which installs it without a prompt when the selected binary is missing or stale.
- `ZTD_TEST_REEXEC` is a registered test-harness environment key.

## Changed

- Generic `/api/v1/data/*` writes return HTTP 405 for every identity, including platform-authority collections. Read-only `GET` and `POST /api/v1/data/{collection}/_query` remain. See [Removed](#removed).
- Operator enrollment transcripts include the auditor-key fingerprint. The bootstrap completion proof checks the Gateway-returned fingerprint against the client's locally computed fingerprint before signing.
- Timed-out agent assignments stop admitting new model and tool calls. An admitted call has a bounded drain interval to return its signed outcome. The executor retains the receipts and seals a partial trace with terminal classification `timeout` and finish reason `WALL_CLOCK_LIMIT`. Verified timeout traces remain verifiable and exportable.
- Evaluation assignments no longer receive an automatic wall-clock timeout derived from a fixed base and estimated governance costs. The Tribunal intent HTTP client no longer applies an estimated aggregate timeout. Existing executor limits and governed stage deadlines still apply.
- Named rollouts stop at the first failed campaign.
- `ztd eval runs cancel` defaults to no publication. Pass `--publish` to publish stopped assignments and the run summary.
- `ztd eval campaigns create` `--hold-context` defaults to true when `--reps > 1` and no `--condition` is given. Pass `--hold-context=false` to start each repetition fresh.
- `ztd gw tunnel route-dns` flag `--api-token` is renamed to `--cloudflare-api-token`.
- `ztd gw security validate` now owns `--pki-dir` and `--secrets-dir`.
- `--public-spectator-allow-container-bind` now also allows the Evaluation Explorer listener and direct cloud VM ingress. Review this flag before enabling it on a public host.
- `ztd operator` and `ztd gw start` accept `--provider llamacpp` and document the llama.cpp keep-alive values.
- `ztd eval` pins `default-suite@1.22.0`, grader `1.12.1`, and `smoke-suite@1.21.0` with 10 scenarios (`SmokeGateScenarioCount = 10`). The `investigations` suite is `1.21.0`. Frozen runs retain the criteria and verdicts they were recorded with. New runs use the current versions.
- `default-suite@1.22.0` excludes `recovery-live-command-error` and `tool-arg-shell-command` under consensus and notary. Scheduling, verification, expected counts, and campaign size displays apply the frozen posture.
- Evaluation Explorer shows deterministic grades beside judged criteria, including a deterministic failure's detail in the criteria strip and failure diagnosis. Judged criteria that share a public label are qualified by the criterion name.
- Evaluation Explorer bootstrap snapshots above 250 projections (`LOCAL_PROJECTION_LIMIT`) use IndexedDB structured clone. Smaller snapshots use `localStorage`.
- The public mirror caches serialized JSON and gzip bootstrap responses.
- Public proof verification publishes the Ed25519 key on the segment log. New segments carry `signing_public_key` (hex; SHA-256 equals `signing_key_id`). The field is excluded from the segment root, so segments signed before it existed stay valid. `ztd public verify-proof` and `ztd public verify-assignment` use that key when `--public-key` and `--key-registry` are omitted. Those flags remain optional pins and must match a published key when both are present. The published commands are `ztd public verify-proof --segments proof-segments.jsonl --artifacts ./proofs` and `ztd public verify-assignment --db <file> --segments proof-segments.jsonl`. Default verification checks Ed25519 signatures and recomputes the hash chain. It does not establish an out-of-band publisher identity. `GET /proof-head` and `GET /proof-segments` fill an empty `signing_public_key` from the mirror's registered key when the key ID matches, without rewriting stored segment bytes. Already-signed `verifier_instructions` and `verification_command` strings stay in the log. The Evaluation Explorer drops a trailing `--public-key <trusted-ed25519-key-hex>` when it displays a catalog command.
- Filesystem search (`search_directory`, `search_file`, `FS_GREP`) is bounded to regular files, and a directory walk stops after 50,000 entries or 15 seconds and returns a result with `truncated` set.
- `ztd test lint` runs the golangci-lint in the Go bin directory ahead of `PATH`, as `make lint` does.
- `ZTD_TEST_*` keys that are not registered no longer bypass registry checks. Listener-capable re-exec helpers are reached only from integration-tagged test entry points.
- `github.com/pkg/sftp` is bumped from v1.13.11 to v1.13.12.
- Operator documents without auditor bindings cannot supply enrolled auditor trust. See [Compatibility](#compatibility).

## Removed

- HTTP routes `POST /api/v1/admin/app-policies/{id}/signers`, `GET /api/v1/admin/app-policies/{id}/signers`, and `POST /api/v1/admin/apps/revoke`. The admin controller and signer controller are deleted, and their route constants are removed from `protocol/constants/api_paths.json`. Signer registration and app revocation go through the governed enrollment and management workflows.
- Legacy direct document writes through `/api/v1/data/*` (PUT, PATCH, DELETE, and POST writes). Settings, users, signers, and revocations must move to governed actions.
- Signer write methods in the trust store (`signer_store_service.go`, `governance/signer_store.go`).
- `ztd eval rollout --continue-on-failure` and the stored `continue_on_failure` field in rollout JSON.
- The `--api-token` alias on `ztd gw tunnel route-dns`. Use `--cloudflare-api-token`.
- `ErrEvaluationTribunalNotLite`. Formation campaigns with a non-Lite Tribunal vote model now run.
- Internal MCP model types `ListResourcesRequest`, `ListPromptsRequest`, and `FieldReadResult` (`internal/services/mcp/models.go`).
- `internal/cli/cmd/cmdtest/reexec.go`, replaced by the `reexec/` package.

## Fixed

- `ztd consensus unbind` failed on every unbind envelope with `TX_PAYLOAD_DECODER_MISSING`. The pub/sub handler now decodes the unbind payload.
- Formation campaigns no longer require the bound Tribunal's vote model to be every formation's Lite model under an enforcing posture. The bound L2 consensus votes with its own model, independent of the scored models.
- An agent reply that uses the Interrogation Protocol is graded on the protocol. Before this, a valid interrogation failed `LeadingLabel` with an empty label.
- `tool-arg-file-path` no longer gates on the exact token `pay…`. Any partial upstream name passes, and either full hostname still fails and is reported as the leak.
- Sentence limits treat ASCII `...` and Unicode `…` consistently, so a masked identifier no longer adds a sentence.
- Filesystem search can no longer be blocked by a FIFO, device, or socket, and no longer runs until the caller's deadline on a large tree. See [Changed](#changed).
- macOS setup no longer installs Homebrew automatically. It stops with instructions to install Homebrew and rerun the setup script.
- Linux keystore setup falls back to an ssh-agent key and fails with a clear error when neither the Secret Service nor an ssh-agent key is available.

- Within one `eval runs start` or `resume` invocation, projected lifecycle `observed_at` values are monotonic across a host wall-clock step. A terminal projection also keeps `ended_at` at or after `started_at` and no later than `observed_at`; Gateway stale-update validation remains active across invocations.
- A governance rejection receipt (`RECEIPT_FAILURE_CODE_GOVERNANCE_REJECTED`) no longer replaces a receipt that already reached a terminal status. A replayed envelope carries the admitted `transaction_id`; its rejection is still appended to the event chain, but the receipt projection stays on the executed receipt that the commitment ledger binds. Before this, a rejected replay made `ztd report` fail `receipt_commitment_crosslink` for the original transaction.
- The evaluation executor rejects a schema-valid `event_receipt_list` request that names another investigation, sets `operator_session_id`, or asks for more than 50 receipts as a model-visible validation failure before dispatch; such a call previously completed and then failed the assignment as `internal_error`.
- Filtered `event_receipt_list` calls retain the full typed query in evaluation evidence, including action type, time, and pagination filters. Previously the executor dropped those filters from the captured retrieval query, so a completed, signed call could become `INVALID_EVIDENCE` when the verifier reconstructed it. Verification still rejects altered query evidence.
- `fs_disk_profile` lists at most 500 entries and stops its walk after 50,000 entries or 15 seconds, returning `truncated: true`. Previously a caller-chosen `max_depth` on a large tree returned an unbounded result: a 26.6 MB profile during doctrine qualification crashed the Gateway (SIGSEGV in the result scrubber; the crash did not reproduce in isolation or under the race detector, and the bound removes the trigger).

## Security

- The generic document and settings HTTP API no longer writes to the Gateway document store. Previously, app and outbound Operator certificates could overwrite or delete trust-bearing records, including signer keys, certificate revocations, users, and settings, through `/api/v1/data/*`. Regression coverage (`data_read_only_integration_test.go`, `trust_store_mutation_integration_test.go`) reproduces those writes on the previous implementation and verifies their rejection.
- App and outbound Operator certificates have explicit method-and-route allowlists. Unlisted pairs fail with HTTP 403 before reaching a handler. Supported app ingress, Tribunal requests, and permitted reads remain available. Outbound Operators keep session validation and their outbound pub/sub transport.
- Delegated app certificates no longer authenticate as their approving user on owner-only routes (`delegated_app_auth_integration_test.go`).
- Connected outbound Operators refresh their L2 trust snapshot from the Gateway. Gateway session validation returns the current consensus membership; the Operator replaces its trust store atomically, never with an older version, before command subscription and reconnect and every 30 seconds over its enrolled mTLS identity. A failed refresh stops execution. Previously, after `ztd consensus unbind` or a rebind with different member keys, a connected Operator kept accepting quorum signatures from removed members at L4 until certificate renewal or restart. Certificate renewal also replaces trust and rejects an empty or version-zero snapshot after a positive binding.
- Explicit runtime paths in Gateway security validation, outbound Operator trust-bundle loading, and MCP CA-bundle loading now use `RuntimeFileService`, including paths relative to the working directory. Runtime path-validation failures propagate instead of falling back to raw filesystem reads. External file paths remain supported; see [Runtime File I/O](../../architecture/storage.md#runtime-file-io).
- Local report verification takes explicit trust anchors as an input, and the auditor key is part of the enrollment contract. Checkpoint signing binds the pruning boundary and auditor identity.
- Operator auditor-key enrollment and signed audit checkpoints are described under [Added](#added). Historical checkpoints are not re-signed; see [Compatibility](#compatibility).
- `--public-spectator-allow-container-bind` now also permits the Evaluation Explorer listener and direct cloud VM ingress. See [Changed](#changed).
- Judge pinning and `content_judgments` are sealed into campaign evidence and verified. Verification rejects altered judgments and grades attributed to another judge variant.
- Dependency update: `github.com/pkg/sftp` v1.13.12 (`go.mod`, `vendor/`).

## Compatibility

v1.5.0 is a minor bump under `INV-REL-VER-10`. It breaks CLI, wire, and evidence contracts, and it requires the Gateway and every Operator to upgrade together. Patch releases in the v1.5.x series remain compatible with v1.5.0.

Breaking changes:

- HTTP: the three admin routes listed under [Removed](#removed) are gone. Generic `/api/v1/data/*` writes return 405. App and outbound Operator certificates receive 403 on any method and route outside the allowlist.
- CLI: `ztd eval rollout --continue-on-failure` is removed. `ztd gw tunnel route-dns --api-token` is renamed. `ztd eval runs cancel` no longer publishes by default. `ztd eval campaigns create --hold-context` defaults to true for repeated runs. `ztd gw security validate` takes `--pki-dir` and `--secrets-dir`. Dispatched-but-failed governed actions exit with code 10.
- Wire (protobuf): `OperatorDocument` fields 38 and 39, `PlatformEnrollmentFingerprints.auditor_key` (field 5), `OperatorRuntimeConfig` fields 24 to 26, `EvaluationCampaignSpec.judge_variant` (field 16), `EvaluationScenarioDefinition.exclude_when_l2_enforced` (field 18), `HeterogeneousAssignmentTarget.designated_role` (field 2), `GovernedDispatchResult.request_envelope` (field 8), and the new failure-code values listed under [Added](#added). Enrollment transcripts change, so an older Operator fails proof verification.
- Evidence: `agent-trace.v10` is introduced. Traces v3 through v9 remain readable. A pre-v10 trace that carries judgments is malformed. Campaigns created before judge pinning keep their stored grades, but their judged criteria fail closed on further execution. Create a new campaign to evaluate them. Grader `1.12.1`, `default-suite@1.22.0`, and the 10-scenario smoke suite apply to new runs.

Upgrade steps:

1. Remove any calls that write through the generic data API. Application record changes use classified governed actions. Platform authority changes use the enrollment and management workflows. Submitting an arbitrary document envelope does not grant authority over trust-bearing collections.
2. Upgrade the Gateway and every outbound Operator together. Existing Operator documents without auditor bindings cannot supply enrolled auditor trust. Use governed enrollment to establish those bindings, and preserve runtime signing keys and authoritative audit stores.
3. Existing canonical databases with unsigned checkpoint schemas fail startup with `ErrAuditCheckpointSchemaIncompatible`, including databases with no checkpoint rows. Archive each authoritative runtime (the Gateway and each Operator) and initialize a fresh root using the [signed-checkpoint upgrade procedure](../../architecture/storage.md#upgrading-to-signed-audit-checkpoints). Do not add signature columns or fabricate signatures over historical checkpoints.
4. The public mirror rejects missing or invalid current-state snapshot markers. Follow the [mirror rebuild procedure](../../architecture/public_spectator.md#upgrade-and-verification) for the disposable mirror store. Preserve canonical evaluation evidence and publisher state.
5. The llama.cpp flags are additive. Existing Ollama flags and defaults are unchanged.
