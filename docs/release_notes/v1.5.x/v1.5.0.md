## [1.5.0] - TBD - Trust and Evidence Integrity (Draft)

## Overview

v1.5.0 readiness work is in progress. These draft notes describe implemented changes; the release gate is not complete.

## Security

- The generic document and settings HTTP API no longer writes directly to the Gateway document store. Previously, app and outbound Operator certificates could overwrite or delete trust-bearing records, including signer keys, certificate revocations, users, and settings, through `/api/v1/data/*`. Regression coverage reproduces those writes on the previous implementation and verifies their rejection without stored changes after removal.

- Delegated app certificates no longer authenticate as their approving user on owner-only routes. The delegated user SAN remains available for governed envelope attribution, L3 suspensions, observe producers, inference, and Tribunal requests. Fully enrolled apps are denied signer registration and app revocation through the admin endpoints in every posture.

- App and outbound Operator certificates now have explicit method-and-route allowlists. Unlisted pairs fail with HTTP 403 before reaching a handler. Supported app ingress, Tribunal requests, and permitted reads remain available; outbound Operators retain session validation and their outbound pub/sub transport.

- Local reports and KSI signature checks use explicitly supplied trust anchors instead of decoding a public key from the evidence's own signer ID. Reports verify receipt signatures, persistence attestations, and commitment-stage linkage. Unknown keys fail verification; receipts that pass KSI verification include verifier identity, version, verification time, and a content digest. These checks detect evidence tampering against the supplied anchors; they do not protect against compromise of the host and its signing-key keystore.

- Explicit runtime paths in Gateway security validation, outbound Operator trust-bundle loading, and MCP CA-bundle loading now use `RuntimeFileService`, including paths relative to the working directory. Runtime path-validation failures propagate instead of falling back to raw filesystem reads. External file paths remain supported; see [Runtime File I/O](../../architecture/storage.md#runtime-file-io).

## Protocol / Changed

- The generic data handlers reject write methods with HTTP 405. Workload identity allowlists can reject a request earlier with HTTP 403. Permitted document and settings `GET` endpoints and read-only `POST /api/v1/data/{collection}/_query` remain available.

- Operator enrollment binds an Ed25519 auditor public key and matching key ID alongside the actuator key, including the auditor-key fingerprint in the enrollment transcript. The local auditor public key is exported as `pki/Auditor_pub.json` under the runtime root, alongside `pki/Actuator_pub.json`. Auditor and actuator lookup remain separate trust roles.

- Signed audit-chain checkpoints bind the pruning boundary, checkpoint hash, creation time, format version, and auditor identity. The runtime rejects databases with the old unsigned-checkpoint schema. Follow the [archive and re-initialization procedure](../../architecture/storage.md#upgrading-to-signed-audit-checkpoints) before starting an upgraded runtime.

- Every registered event declares its transports. Pub/sub and SSE publishers reject undeclared transports before publishing or persisting the projected event; locally persisted facts declare `local`.

- Operator bootstrap completion proofs now include the auditor-key fingerprint returned by the Gateway. The client checks it against its locally computed fingerprint before signing, preventing enrollment proof mismatches after the auditor-key contract change.

- Timed-out agent assignments stop admitting new model and tool calls. An admitted call has a bounded drain interval of one approval budget plus one inference dispatch budget to return its signed outcome; cancellation before the assignment deadline still interrupts that wait. The executor retains the receipts, closes the Data ledger bracket, and seals a partial trace with terminal classification `timeout` and finish reason `WALL_CLOCK_LIMIT`. Verified timeout traces receive a failed assignment lifecycle and remain verifiable and exportable. An unknown remote outcome still fails evidence verification when it leaves a ledger gap.

- Evaluation assignments no longer receive an automatic wall-clock timeout derived from a fixed eight-minute base and estimated governance costs. The Tribunal intent HTTP client also removes its estimated aggregate timeout and uses the caller's context. Existing executor limits and governed stage deadlines still apply. `eval runs start` and `resume` (including `execute`) add an overall assignment deadline only with a positive `--assignment-timeout`; zero adds none, and negative values fail before runtime state is loaded. Parent cancellation and deadlines remain effective.

- Within one `eval runs start` or `resume` invocation, projected lifecycle `observed_at` values are monotonic across a host wall-clock step. A terminal projection also keeps `ended_at` at or after `started_at` and no later than `observed_at`; Gateway stale-update validation remains active across invocations.

- Evaluation campaigns freeze one pinned judge (`EvaluationCampaignSpec.judge_variant`) that scores every judged criterion, so a scored model no longer grades its own answers. `ztd eval campaigns create --judge <served tag>` selects it from the model registry (default `gemma4:e4b`), and `ztd eval rollout run` uses the default. The judge dispatches under its own single-entry model registry, and verification rejects any grade attributed to another variant. Campaigns created without a judge keep their stored grades, but their judged criteria fail closed on further execution; create a new campaign. See `INV-EVAL-CAMP-42` in [Evaluations](../../architecture/evals.md).

- Empty investigation history accepts equivalent wording through the receipt-bound `history-grounding` judge criterion. The judge sees the recorded query result; the verifier reconstructs that prompt from authenticated evidence. Exact returned transaction IDs and action types remain deterministic checks for nonempty results.
- Scenario semantic content is judged per criterion. `ScenarioContentCheck.JudgedCriteria` entries are decided by the campaign's pinned judge under rubric `criterion-v1`, with one governed dispatch per criterion, and are sealed in `agent-trace.v10` as `content_judgments`. Deterministic checks remain in place. Scenario content passes only when every deterministic check passes and every judged criterion is met, and each verdict appears as a `content:<criterion id>` semantic grade. `policy_decision` refusal evidence comes from the scenario's `RefusalCriterion`. Traces v3 through v9 remain readable, and a pre-v10 trace that carries judgments is malformed. The grader is `1.12.1` and the built-in suite is `default-suite@1.20.0`. See `INV-EVAL-CAMP-43` through `INV-EVAL-CAMP-45` in [Evaluations](../../architecture/evals.md).

- The Evaluation Explorer shows deterministic grades beside judged criteria. Previously, it hid them whenever an assignment had any semantic grade. A deterministic failure, such as a forbidden answer term, now appears in the criteria strip, the graded count, the run table, and the failure diagnosis, together with the grader's verbatim detail. Judged criteria that share a public label are qualified by the criterion name, for example `Judged answer requirement: refuses request`.

- `ztd consensus unbind` clears the bound consensus through the governed `PLATFORM_ENROLLMENT_UNBIND_CONSENSUS` action (`DELETE /api/v1/auth/platform-enrollments/consensus`). It is owner-only. Under `ratify` and `notary` the Gateway suspends it for passkey approval (HTTP 202) and the CLI prints the approval URL and transaction. A cleared binding is returned with `enabled: false` and an incremented `binding_version`; unbinding again returns HTTP 404. The pub/sub handler now decodes the unbind payload; before this, every unbind envelope failed with `TX_PAYLOAD_DECODER_MISSING`.

- The `ztd` CLI exits with status 10 (`ExitCodeActionExecutionFailed`) when a command's governed action was dispatched, and approved where required, but failed in execution (`ErrActionExecutionFailed`), for example `ztd auth approve --cli` on a transaction whose handler then failed. Its signed FAILED receipt is the evidence. Every other command error still exits 1.

- A governance rejection receipt (`RECEIPT_FAILURE_CODE_GOVERNANCE_REJECTED`) no longer replaces a receipt that already reached a terminal status. A replayed envelope carries the admitted `transaction_id`; its rejection is still appended to the event chain, but the receipt projection stays on the executed receipt that the commitment ledger binds. Before this, a rejected replay made `ztd report` fail `receipt_commitment_crosslink` for the original transaction.

- `ZTD_TEST_REEXEC` is a registered test-harness environment key. Unregistered `ZTD_TEST_*` keys no longer bypass registry checks. Listener-capable re-exec helpers are reached only from integration-tagged test entry points.

- Sentence limits treat ASCII `...` and Unicode `…` masks consistently, so a masked identifier does not add a sentence to the response.

- An agent reply that uses the Interrogation Protocol is graded on the protocol instead of failing the scenario's answer rules. Before this change, a reply such as a valid interrogation about a status feed with no status field failed `LeadingLabel` with an empty label. A valid interrogation is the entire reply: exactly three numbered, strictly yes/no questions. One parser (`ParseInterrogation`) now serves both the executor and the grader, replacing a lenient executor parser that accepted one to three questions. A malformed block fails with a typed `ErrEvaluationInterrogation*` sentinel. Only a valid interrogation can earn a scripted follow-up. Grader `1.12.0`, built-in suites `1.19.0`. Stored runs keep their frozen grader.

- `smoke-suite` grows from 5 to 10 scenarios (16 cells per model). The rollout smoke gate passes a model whose run completes and verifies, so the suite now exercises every role, every trajectory policy, history retrieval, tool arguments, judged criteria, JSON fields, leading labels, guided recovery, governed denial, and file state. A unit test enforces that coverage. Within that coverage, scenarios were chosen for how well they separated models in the eval-init campaigns. `tech-error-diagnosis`, whose Lite-only scripted follow-up cannot be reached, is replaced.

- The `cites-retention-rule` content criterion explicitly credits supplied security rules and stated retention prohibitions without requiring a named policy document. Fresh campaigns use grader `1.12.1` and built-in suites `1.20.0`; frozen runs retain their original criteria and verdicts.
- `tool-arg-file-path` no longer gates on the exact token `pay…`: the prompt asks for a partial name such as `pay…`, any partial upstream name (`pay…` or `payments`) passes, and either full hostname still fails and is now reported as the leak. The check stays deterministic, like the rest of the tool-argument family. Built-in suites `1.21.0`.
- The evaluation executor rejects a schema-valid `event_receipt_list` request that names another investigation, sets `operator_session_id`, or asks for more than 50 receipts as a model-visible validation failure before dispatch; such a call previously completed and then failed the assignment as `internal_error`.
- `default-suite@1.22.0` freezes posture eligibility in each scenario definition. `recovery-live-command-error` and `tool-arg-shell-command` are excluded under consensus/notary because required shell execution can be denied by L2. Doctrine/ratify keep 56 cells per model; consensus/notary schedule 52. Scheduling, independent verification, projected expected counts, and campaign size displays apply the frozen posture. `smoke-suite` and `investigations` remain at `1.21.0`.
- Filtered `event_receipt_list` calls retain the full typed query in evaluation evidence, including action type, time, and pagination filters. Previously the executor dropped those filters from the captured retrieval query, so a completed, signed call could become `INVALID_EVIDENCE` when the verifier reconstructed it. Verification still rejects altered query evidence.
- A formation campaign no longer requires the bound Tribunal's vote model to be every formation's Lite model under an enforcing posture (`ErrEvaluationTribunalNotLite` is removed). As in a model-role campaign, the bound L2 consensus votes with its own model, independent of the scored models.
- `search_directory`, `search_file` and `FS_GREP` read only regular files, so a FIFO, device or socket (directly or through a symlink) can no longer block a search. A directory walk stops after 50,000 entries or 15 seconds and returns a completed result with `truncated` set, instead of running until the caller's deadline; an evaluation model that searched `/` previously spent about eight minutes there and the assignment failed as invalid evidence.
- `./ztd test lint` runs the golangci-lint in the Go bin directory ahead of PATH, as `make lint` does. Previously an older copy earlier on PATH could run and fail with `the Go language version (go1.26) used to build golangci-lint is lower than the targeted Go version`. When the selected binary is missing or was built with a Go older than `go.mod` targets, the command names the problem and offers to run the new `make golangci-lint-install` target, which installs only the pinned golangci-lint. `--yes` installs without asking; declining or giving no input exits without installing.

- `eval runs cancel` defaults to no publication. Pass `--publish` to publish stopped assignments and the run summary; cancellation does not inherit the start command's publication flag.

## Performance

- Evaluation Explorer bootstrap ingestion reuses parsed payloads, defers source-record serialization, decodes campaign envelopes once, and avoids copying the growing campaign context for each assignment. Validation and malformed-record rollback remain enforced.
- Small browser bootstrap snapshots use `localStorage`; snapshots above 250 projections use IndexedDB structured clone. Large writes and quota failures remove stale synchronous-cache data. Startup installs the snapshot and opens SSE before saving the new cache.
- The public mirror caches serialized JSON and gzip bootstrap responses, invalidates them for source freshness and proof-summary changes, and handles conditional requests before writing compressed bytes. Response decoding and encoding run outside the mirror mutation lock after a coherent snapshot capture.

## Upgrade

Remove calls that write through the generic data API before upgrading the Gateway. Application record changes use classified governed actions. Platform authority changes use the corresponding enrollment and management workflows; submitting an arbitrary document envelope does not grant authority over trust-bearing collections.

Upgrade the Gateway and outbound Operators together for the auditor-key enrollment contract. Existing Operator documents without auditor bindings cannot supply enrolled auditor trust; use governed enrollment to establish those bindings and preserve runtime signing keys and authoritative audit stores.

Existing canonical databases with unsigned-checkpoint schemas fail startup with `ErrAuditCheckpointSchemaIncompatible`, including databases with no checkpoint rows. Archive each authoritative runtime and initialize a fresh root using the [signed-checkpoint upgrade procedure](../../architecture/storage.md#upgrading-to-signed-audit-checkpoints). Do not add signature columns or fabricate signatures over historical checkpoints.

Mirror startup rejects missing or invalid current-state snapshot markers rather than backfilling an old schema. Follow the [mirror rebuild procedure](../../architecture/public_spectator.md#upgrade-and-verification) for the disposable mirror store; preserve canonical evaluation evidence and publisher state.

These changes remove HTTP contracts and change enrollment contracts, so they belong to the v1.5 minor release. Full release qualification remains open. The offline tamper matrix and other scope deferrals are listed below.
