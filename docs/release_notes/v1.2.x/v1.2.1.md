# v1.2.1 Release Notes

Status: unreleased; qualification pending.

## Changed

- The native `run_shell_command` is the single shell tool exposed to evaluation models. `TribunalCommands` routes its proposed arguments through Gateway Tribunal authoring, voting, risk assessment and review.
- Tribunal members return strict JSON containing one executable and ordered argv. No shell text normalization occurs. Timeout and working directory are owned by orchestration and reviewed before dispatch. Tribunal requests cannot fan out over remote hostnames.
- Approved arguments cross governance as `MCP_CALL run_shell_command`, using the exact approved canonical JSON. Native execution results and signed Operator receipts remain the evidence boundary; Tribunal approval never substitutes for L2 quorum or L3 human approval.
- Trace steps use the shared typed execution arguments, and tool traces retain both proposed and approved arguments.
- New agent traces seal as `agent-trace.v8`, which adds `tool_calls[].approved_arguments_json`. Verification binds it to a Tribunal review step's canonical arguments and rejects it on earlier versions. The public `role_transcripts` tool call carries the same field, and the evaluation explorer shows approved arguments when they differ from the proposal. `agent-trace.v3` through `v7` remain readable and verifiable.
- Tribunal proposals and approved arguments use sorted-key canonical JSON, the form the inference and evaluation verifiers require.
- Investigation fixture governed probes name one executable and argv (`{"command":"sh","args":["./check.sh"]}`) instead of shell text.
- The required Go toolchain is 1.27.3, which fixes GO-2026-6809 in `crypto/x509`.

## Compatibility

The synthetic intent-only shell tool is removed, and new traces carry no string command step fields. `CandidateOutput.command` and `ReviewOutput.command` are kept only so v1.2.0 `agent-trace.v7` Tribunal steps still decode; an `agent-trace.v8` trace that sets them is rejected. Catalog digests change. Campaign import pins `agent-trace.v8`, so campaigns sealed earlier stay in history under their own release, and `ztd public verify-agent-trace` still verifies them. Campaigns and Tribunal traces recorded on the previous tool catalog remain in campaign history attributed to the release they measured. New campaigns freeze against the new catalog, and runtime execution provides no compatibility shim for the removed tool. Historical release notes retain their original scope.

Tribunal authors one executable with argv, executed without a shell. Pipelines, chaining, redirects, globs and substitutions are unavailable under this contract. Investigation baselines that assumed those compositions require reassessment; model compliance and score comparisons still require a scored campaign.
