## [1.2.0] - 2026-10-20 - Governed Evaluation and Evidence

### Overview

v1.2.0 prepares governed evaluation execution and its evidence pipeline following v1.1.3. This is a release preparation draft: complete diff and documentation review, native-platform qualification, and signed public compliance evidence remain pending. Linux smoke and deterministic qualification results are recorded below. The planned UTC tag date is October 20, 2026.

### Added

- Campaign-local sealed provider attempt, observation, and model provenance evidence for offline compliance verification. Missing sealed witness records fail report generation.
- Real-Gateway evaluation and conformance fixtures with distinct outbound Operator runtimes, plus cross-process evaluation-loop qualification under ratify and notary.
- Campaign judge evidence. Judge receipts bind the score result to the signed receipt summary, and `INVALID_EVIDENCE` and `PROVIDER_FAILED` assignments are never judged.

### Changed

- CLI and passkey approval handling, outbound proof verification, and CLI identity/session binding. Full posture and ingress review remains open.
- Evaluation context, assignment traces, and browser consumers. Detailed delivery claims await completion of the release diff review.
- Campaign assignment import, live and recovered, accepts only agent-trace v7, and the assignment verifier applies the same pin. An earlier-version campaign trace is recorded as `INVALID_EVIDENCE` with no grades. `ztd public verify-agent-trace` still verifies published v3 through v6 traces.
- Compliance assertion catalog 2.1.0: `ZTD-DLP-BOUNDARY-001`, `ZTD-DLP-REHYDRATE-001`, and `ZTD-CM-STATE-001` are version 2.1.0 with `gateway`/`operator` component scope, and catalog `component_scope` values are a closed set.
- Provider-boundary observation and model provenance are optional for inference. With no Observer or Provenance Operator connected, a campaign attempt proceeds without that window; `ztd eval runs start --require-observation`, `--require-provenance`, or `--require-witness` enforces coverage at verification.
- The Operator bootstrap client requires TLS 1.3.
- `ztd gw tunnel create --ca-bundle` sends the Gateway internal hostname as origin SNI by default. `--origin-server-name` without `--ca-bundle` is rejected.
- Platform enrollment app-name validation has one owner shared by the CLI and Gateway; a reserved or invalid app name returns HTTP 400 instead of 500.

### Removed

- PID-file-only process termination fallback. Deployment stop uses verified process discovery and fails closed when discovery fails. Host deployment requires the canonical `ztd`/`ztd.exe` executable name.
- The legacy evaluation SUT package, its `/ztd-sut` routes, and SUT timing constants. External SUT support is deferred.
- The `ErrEvaluationSystemLaneUnavailable` sentinel and its classifier clause.

### Fixed

- The `audit_receipt_list` tool schema no longer requires `operator_session_id`. Operator-local queries run without a session filter; Gateway-native queries still require one.
- External MCP server help examples use the maintained `ztd gw start` command.
- Host deployment stop propagates signal and exit-wait failures; a worker is reported stopped only after observed exit. Invalid worker executables are rejected before replacing an existing worker or truncating its log.
- Runtime process exit waiting and Operator discovery use platform-specific process handles instead of polling.
- The public mirror rejects ingest when no token is configured.
- `@ztd/adapter` resolves under plain Node ESM: the package root barrel exists, relative imports carry `.js` specifiers, and its error classes are exported.
- The evaluation explorer seed and replay scripts require the Gateway-owned public mirror and fail closed on snapshot, status, or push errors; the development supervisor exits with Vite's exit code.
- The checked-in base init campaign queue declares 41 cells per model, matching the default suite.

### Tests

Qualification is in progress. Earlier baseline passes measure v1.1.3-versioned source at `08eb8c6ec125dfab4b55c6e2442e1857bb6f9971`; they do not qualify the prepared v1.2.0 candidate. Exact candidate commands, outcomes, source and binary provenance, and exclusions will be recorded after final source and embed updates.

### Documentation

- Added this release draft and the v1.2.x changelog section.
- Updated the README version reference, authoritative runtime database path (`data/ztd.db`), and lint/chaos suite descriptions.
- Added current qualification entry points to agent and contributor instructions. Audited the protocol and public spectator guides; documented inference failure observation receipts.
- Version declarations and the generated Explorer embed are synchronized with `VERSION`.

### Compliance Evidence

Pending. No signed v1.2.0 public compliance bundle or canonical projections have been generated. Core-platform smoke evidence must be retained separately from the signed public bundle. Publication remains blocked until both satisfy the release process.

### Deferred

- Hosted provider-transparent campaigns and OIDC/Okta federation remain deferred; current model inventory and enrollment changes do not establish support for them.
- Formation repetitions beyond one, held context for formations, additional Triage/Dash/Codex execution roles, durable case memory, external SUT support, expanded episode verification, public chronology/redaction, and formal statistical analysis remain deferred.
- No fresh live-provider run has been performed for this release preparation. Deterministic scripted-provider results establish pipeline behavior, not live model quality.
