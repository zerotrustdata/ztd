## [1.2.0] - 2026-10-20 - Production Tribunal, Governed Approvals, and Investigation Campaigns

### Overview

v1.2.0 moves command authoring behind a Gateway-side Tribunal, closes the CLI and outbound-Operator approval
paths for L3, makes consensus bindings K-of-N, and gives evaluation campaigns fresh and persistent
investigations with sealed `agent-trace.v7` evidence. The legacy evaluation SUT and the JSON agent-tool registry
are removed.

Protocol changes are additive except where noted under **Removed**; retired field and enum numbers are reserved.

### Highlights

* **Production Tribunal** — New `POST /api/v1/operators/intents` (`internal/services/tribunal/`,
  `internal/services/gateway/tribunal_intent.go`). A caller submits a plain-language intent; the Tribunal runs
  generate → marshal (risk) → audit as governed `INFERENCE` dispatches, then dispatches the approved command as an
  ordinary governed `EXECUTE_BASH` under the caller's identity. It never supplies or replaces L2 or L3 proof.
  Outcomes: `APPROVED`, `NO_CONSENSUS`, `BLOCKED` (high risk, with rationale), `AUDIT_FAILED`,
  `INFERENCE_FAILED`. Requires an app workload identity with a delegated user (`INV-GW-GOV-07`).
* **CLI and outbound L3 approval** — `ztd auth approve --cli` signs the transaction hash with the enrolled CLI
  certificate. Outbound Operators verify L3 proof locally: notary proofs carry the CLI certificate chain
  (`cli_certificate_der`, `cli_intermediates_der`) or a `PasskeyVerificationContext` (user, credential, COSE
  key, RP ID, allowed origins). Approval logic lives in `internal/governance/cli_approval.go` and
  `passkey_approval.go`; outbound verification is in `internal/services/governance/outbound_l3_notary.go`.
* **K-of-N consensus bindings** — `ztd auth enroll consensus bind` accepts repeated `--member-app` and
  `--quorum`. A multi-member set must state its quorum, and the primary app must be a member. The Gateway and the
  L5 handler resolve membership through one owner (`models.ResolveConsensusMembership`). New enrollment payload
  fields: `consensus_member_app_ids = 22`, `consensus_quorum = 23`.
* **Investigation campaigns** — `ztd eval campaigns create` gains `--investigation fresh|persistent:<id>`,
  `--data-operator`, `--condition longitudinal|control|held-context`, `--formations`, and `--posture`.
  `--hold-context` now defaults to `false`. Campaigns can set `tribunal_commands`, so the model states intent
  through `run_commands_with_operator` and the Tribunal writes the command.
* **Sealed campaign evidence** — Each assignment seals its full conversation and tool trajectory as a
  content-addressed `agent-trace.v7` envelope. Provider-boundary observation and model provenance have per-campaign
  witness policies (`INTERIM` / `STRICT`); `ztd eval runs start --require-witness`, `--require-observation`,
  and `--require-provenance` enforce them at verification.
* **Event-driven runtime** — Process-exit waiting uses platform-specific process handles
  (`internal/cli/platform/process_exit_*.go`). `ztd eval runs` follows stop and status events over the existing
  event stream. The `@ztd/adapter` SSE polling fallback is gone.

### Added

* **Protocol**
  * `ztd/tribunal/v1/tribunal.proto`: `TribunalIntentRequest`, `TribunalIntentResult`, `TribunalMemberCall`,
    `TribunalStage`, `TribunalOutcome`.
  * `common.proto`: `PasskeyVerificationContext`; notary proof fields `cli_certificate_der = 7`,
    `passkey_context = 8`, `cli_intermediates_der = 9`; `pending_dispatch = 3`; consensus enrollment fields
    `consensus_member_app_ids = 22`, `consensus_quorum = 23`.
  * `eval.proto`: `EvaluationInvestigationMode` (`FRESH`, `PERSISTENT`), `EvaluationInvestigation`,
    `EvaluationWitnessPolicy` (`INTERIM`, `STRICT`), `provider_observation_policy = 14`,
    `model_provenance_policy = 15`, `formation_stack_set_digest = 15`, `tribunal_commands = 17`.
  * `operator.proto`: `observation_receipts` on inference results and failures;
    `GOVERNANCE_REJECTION_CODE_MCP_TARGET_MISMATCH = 25`.
* **API** — `POST /api/v1/operators/intents`.
* **CLI**
  * `ztd auth approve --cli`
  * `ztd auth enroll consensus bind --member-app <id> --quorum <n>`
  * `ztd eval campaigns create` flags listed above
  * `ztd eval runs start --require-witness`
  * `ztd public verify-proof --segments --public-key --key-registry`
  * `ztd test eval-loop [--posture ratify|notary] [--live-ollama-endpoint --live-model]`: cross-process
    evaluation loop against real outbound Operators. The live mode reaches Ollama only through the governed
    Inference Operator.
* **Assignment audit database** (`internal/services/assignmentaudit/`) — Holds one assignment's public feed
  records. Its signed proof segment authenticates it by SHA-256, and `ztd public verify-assignment` verifies it
  offline.
* **Constants** — `ErrScrubbingTokenUnresolved`, `ErrScrubbingKeyCollision`, `ErrMCPNativeToolHostMissing`,
  `ErrProcessNotFound`, `ErrUnsupportedPlatform`, `ErrConfigLeafCertTTLInvalid`,
  `ErrGovernanceCLISessionRequired`, `ErrEvaluationInvestigationInvalid`,
  `ErrMCPAuditReceiptListInvestigationReq`.

### Changed

* **Agent tools** — The evaluation agent tool catalog is built from native tool definitions
  (`agent_native_tools.go`), not a JSON registry.
* **Campaign trace pin** — Live and recovered campaign import accepts only `agent-trace.v7`. Older campaign
  traces are recorded as `INVALID_EVIDENCE` and are not graded. `ztd public verify-agent-trace` still verifies
  published v3–v6 traces.
* **Judging** — `INVALID_EVIDENCE` and `PROVIDER_FAILED` assignments are never judged. Judge receipts bind the
  score to the signed receipt summary.
* **Compliance catalog 2.1.0** — `ZTD-DLP-BOUNDARY-001`, `ZTD-DLP-REHYDRATE-001`, and `ZTD-CM-STATE-001` are
  scoped to `gateway`/`operator`, and `component_scope` is a closed set.
* **Operator bootstrap** — The bootstrap client requires TLS 1.3.
* **Tunnels** — `ztd gw tunnel create --ca-bundle` sends the Gateway internal hostname as origin SNI.
  `--origin-server-name` without `--ca-bundle` is rejected.
* **Enrollment** — App-name validation has one owner shared by the CLI and Gateway. A reserved or invalid name
  returns HTTP 400, not 500.
* **Scrubbing boundary** — Rehydration fails closed on unresolved tokens and key collisions.

### Removed

* **Legacy evaluation SUT** — `internal/services/evaluation/sut/`, the `/ztd-sut` routes, SUT timing
  constants, and the `ScoredTurnRequest`/`ScoredTurnEvent`/`InvestigationSeed` protocol messages.
* **JSON agent-tool registry** — `protocol/constants/agenttools/`.
* **`provider_boundary_observation_ref = 32`** — Reserved. Observations travel as `observation_receipts`.
* **`PLATFORM_COMPONENT_KIND_ENSEMBLE`** — Number 2 and the name are reserved.
* **Assignment audit vault encryption** — `--vault-key` is removed from public assignment verification. The
  database carries only already-published public feed records and is authenticated by its signed proof segment.
* **PID-file-only process termination** — Deployment stop uses verified process discovery and fails closed.
  Host deployment requires the canonical `ztd`/`ztd.exe` executable name.
* **`@ztd/adapter` SSE polling fallback** (`src/sse/polling.ts`).
* **Sentinels** — `ErrEvaluationSystemLaneUnavailable` and the per-field `ErrCLIL3*` sentinels. CLI L3
  verification now uses `ErrGovernanceCLISessionRequired` and the shared approval owner.

### Fixed

* `audit_receipt_list` no longer requires `operator_session_id` for Operator-local queries. Gateway-native
  queries still require it.
* Host deployment stop propagates signal and exit-wait failures and reports a worker stopped only after its exit
  is observed. Invalid worker executables are rejected before an existing worker is replaced or its log is
  truncated.
* The public mirror rejects ingest when no token is configured.
* `@ztd/adapter` resolves under plain Node ESM: it has a root barrel (`src/index.ts`), `.js` import specifiers,
  and exported error classes.
* Evaluation explorer seed and replay scripts fail closed on mirror snapshot, status, or push errors. The dev
  supervisor exits with Vite's exit code.
* External MCP server help examples use `ztd gw start`.
* The base init campaign queue declares 41 cells per model, matching the default suite.
