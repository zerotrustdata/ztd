## [1.3.0] - 2026-10-22 - Tribunal Consensus and Governed Execution

Qualification pending. Planned tag date: 2026-10-22.

v1.2.1 was never published. Campaigns that record release v1.2.1 measured v1.3.0 pre-release candidates.

## Overview

v1.3.0 makes the Gateway-hosted Tribunal an L2 consensus that votes only on state changes. It replaces every shell path
with one `run_shell_command` contract: one executable and argv, authored under strict JSON schemas. It qualifies each
governed ingress with real-workflow conformance runs. Event receipts move onto the `events` chain, and UEI scrubbing
tokens name the runtime that minted them.

This is a minor release that breaks compatibility (`INV-REL-VER-10`). Upgrade the Gateway and every outbound Operator
together, and start both from a new runtime root. `ztd auth enroll consensus`, `ztd auth consensus` and
`ztd eval campaigns create --posture` are removed. Bindings require a consensus provider. Agent tool catalogs and their
digests change. Runs started before this release cannot be executed or resumed. Details are under **Removed** and
**Compatibility**.

## Changed

- The evaluation explorer Models page defaults to all releases. Selecting a specific release in the URL or release filter still limits the catalog and leaderboard to that release.

- Event receipts live on the `events` row. The `receipts` table is gone. The current stage of a transaction is the `ztd.v1.operator.receipt.recorded` chain event whose `event_receipt_status` is not null. Earlier stages stay on the chain with those columns null. Receipt lookups by acting app use `idx_events_event_receipt_acting_app` on `events`.
- `GET /api/v1/audit/receipts` and `GET /api/v1/audit/receipts/export` are now `GET /api/v1/audit/event-receipts` and `GET /api/v1/audit/event-receipts/export`. List JSON uses `event_receipts`. Report JSON uses `event_receipts` and `event_receipts_count`. Summary JSON uses `event_receipts_summary` and `event_receipts_total`.
- `ztd audit receipts` is now `ztd audit event-receipts`. `ztd report all` writes `event_receipts.csv` instead of `receipts.csv`. The default audit export filename is `event-receipts-export.json`.
- `L2Metadata` field numbers 3 and 4 are reserved. They held pre-release deliberation fields that no v1.2.0 build carried. Consensus providers are required on every binding, and an empty provider is rejected.

- The native `run_shell_command` is the single shell tool exposed to evaluation models. `TribunalCommands` routes its proposed arguments through Gateway Tribunal authoring, voting, risk assessment and review.
- Tribunal members return strict JSON containing one executable and ordered argv. No shell text normalization occurs. Timeout and working directory are owned by orchestration and reviewed before dispatch. Tribunal requests cannot fan out over remote hostnames.
- Approved arguments cross governance as `MCP_CALL run_shell_command`, using the exact approved canonical JSON. Native execution results and signed Operator receipts remain the evidence boundary; Tribunal approval never substitutes for L2 quorum or L3 human approval.
- Trace steps use the shared typed execution arguments, and tool traces retain both proposed and approved arguments.
- New agent traces seal as `agent-trace.v8`, which adds `tool_calls[].approved_arguments_json`. Verification binds it to a Tribunal review step's canonical arguments and rejects it on earlier versions. The public `role_transcripts` tool call carries the same field, and the evaluation explorer shows approved arguments when they differ from the proposal. `agent-trace.v3` through `v7` remain readable and verifiable.
- Tribunal proposals and approved arguments use sorted-key canonical JSON, the form the inference and evaluation verifiers require.
- Investigation fixture governed probes name one executable and argv (`{"command":"sh","args":["./check.sh"]}`) instead of shell text.
- The required Go toolchain is 1.27.3.
- The Gateway can host L2 consensus itself: the Tribunal panel (`tribunal-axiom`, `tribunal-concord`, `tribunal-variance`, `tribunal-pragma`, `tribunal-nemesis`) votes 3-of-5 by default. Each member is an enrolled app with a sealed Ed25519 signing key. Each vote is one governed inference on the binding's pinned model tag and digest. A malformed answer or anything other than approve counts as a signed deny; a member that cannot run or sign casts no vote.
- New `ztd consensus` command group: `status`, `enroll app`, `enroll tribunal --model <tag> [--quorum]`.
- New `GET /api/v1/audit/consensus-votes?tx_id=<id>` returns every recorded L2 member vote (member, outcome, scrubbed reason and failure) for one transaction, oldest first.
- `/health` gains a `consensus` readiness object. `governance_ready` is false under an L2 posture until a consensus is bound and has quorum-many usable signers. `ztd gw status` shows a Consensus row.
- Eval campaigns refuse to start under an L2 posture without a ready consensus.
- An eval campaign no longer freezes a governance posture, and `ztd eval campaigns create` drops `--posture`. Each run freezes the live Gateway posture and consensus binding when it starts: provider, vote kind, Tribunal model tag and digest, K-of-N members and a binding digest. `runs start` prints them. One campaign can run under any posture or Tribunal model. `runs execute` and `runs resume` refuse a run once the Gateway's posture or binding differs from what it froze (`ErrEvaluationRunGovernanceChanged`), so a rebind such as `consensus enroll tribunal --model <tag>` never mixes two vote models in one run.
- `read_file` and the new search tools share one sensitive-path check (`security.IsSensitiveReadPath`); a refused read wraps `ErrSensitivePath`.
- The scenario hint lint rejects a workspace-sourced argument that names no workspace path.
- The evaluation explorer's Runs panel colors each run's bar by the same verdicts as the Live activity results: Passed, Model failed, and No verdict for assignments that ended without one, such as unavailable or invalid evidence. Before, it showed assignment lifecycle, so an assignment that ended without a verdict was drawn as completed or failed.
- The built-in suites are `default-suite@1.7.0` and `investigations@1.7.0`. The migrated scenarios and `tool-arg-shell-command` are at `1.5.0`; the investigation scenarios are at `1.1.0`.
- Tribunal L2 votes only on state-change actions. `governance.L2Enforced` (`internal/services/governance/l2_consensus.go`) selects a non-bootstrap action whose `ChangesState` is true for its target. Under `consensus` and `notary`, inference, provider-boundary and model-provenance observations, Ollama model inventory, residency and release, and registered read-only MCP targets get no vote round. An unknown target fails closed as a state change.
- Ollama model release is the typed `OLLAMA_MODEL_RELEASE` action. It previously ran as an `EXECUTE_BASH` command (`operator model release <tag>`), and the hidden CLI subcommand that emitted it is removed. It is a mutation, so L3 applies under `ratify` and `notary`, and it is not a state change, so L2 does not gate it. Model pull and copy remain `EXECUTE_BASH` and stay L2-gated.

## Added

- Opt-in typed System One decision inference for Tribunal consensus, with local digest pinning, a fixed hosted Jev endpoint, vault credential reads, frozen member thresholds, pinned Operator routing and campaign provider isolation. Hosted access defaults off. No key is configured, no decision model is production-qualified, and hosted rollout is deferred. See [Decision Model Votes](../../architecture/consensus.md#decision-model-votes-opt-in).

- Native `search_file` searches exactly one file and refuses a directory. Native `search_directory` searches a directory recursively, with optional `include` globs, and refuses a file. Each refusal names the other tool. Both delegate to the executing runtime's `FsGrepService`, skip sensitive files, scrub every returned line, and return an error on every failure, so the Actuator signs a `FAILED` receipt.

- `ztd auth approve --deny <transaction_hash>` denies a suspended L3 transaction from the enrolled CLI session over mTLS and prints the Operator-signed `L3_DENIED` rejection receipt. The command fails if the receipt names another transaction or carries another rejection. `--deny` and `--cli` are mutually exclusive.
- `ztd eval runs repair <run> --projection` reopens a terminal Gateway run projection that the run's local store contradicts. An example is a paused run projected as `cancelled` by an earlier release. Repair holds the run lease and posts `waiting` with `reopens` naming the terminal status. The Gateway applies it only while the projection holds exactly that status, and logs each reopen. Resume refusals for a resumable local run name this command.
- `ztd test conformance-loop [--posture doctrine|consensus|ratify|notary]` runs `ztd eval conformance run` against a dedicated Data Operator and the embedded Operator on an isolated stack, driven through `ztd mcp stdio`. Under ratify and notary the runs are attended, and the enrolled CLI owner answers each suspended case with `ztd auth approve --cli` or `--deny`. Every applicable case must pass and verify offline, and both runtimes' audit chains and `report all` evidence must verify.

- `ztd mcp stdio` proxies `initialize` to the Gateway like every other MCP request. Each proxied request has a per-call timeout longer than the Gateway's dispatch wait.

- The `governance-conformance` suite is version `1.1.0`. Its `MCP_STDIO` ingress drives `ztd mcp stdio`, the bridge an agent spawns.

- Embedded-only conformance runs execute every applicable case. With no outbound Data Operator selected, the embedded Operator executes the outbound dispatch and CLI cases.

- A2A ingress is opt-in. A Gateway without `--a2a-downstream-url` mounts no A2A route, reports `a2a_ingress: false` on `/health`, and its A2A conformance cases are not applicable.

## Removed

- Native `log_stream_filter`. Use `search_file` or `search_directory`.
- Native `run_commands_with_operator` tool and its `agentToolRunCommands` constant.
- `internal/services/tribunal/normalize.go`.
- Tribunal results no longer set the string `command` field. New steps set only `arguments`; `CandidateOutput.command` and `ReviewOutput.command` are decode-only for `agent-trace.v7` and earlier.
- Tribunal `EXECUTE_BASH` dispatch in `campaign_tribunal_commands.go`.
- `ztd auth enroll consensus` and `ztd auth consensus`. Use `ztd consensus`.
- `ztd eval campaigns create --posture`.
- Hidden `ztd operator model release` subcommand.

## Fixed

- L4 rejects an enabled consensus policy with a quorum outside one through its member count, including a zero quorum that previously accepted no votes. Tribunal deliberator construction rejects missing required dependencies and propagates the error through Gateway startup.
- Tribunal consensus vote parsing now rejects a missing or null `reason` field as a signed deny; an empty string remains valid.
- Every Tribunal shell-authoring call now carries its role's JSON response schema, so a live provider can return what the strict decoders accept. Before, Marshal answered in prose, which failed closed as `HIGH`. The Auditor added `timeout` to `revised_arguments`, or returned `APPROVE` together with a revision, and either answer failed the audit. Candidates and Auditor revisions are the authored `{command, args}` only. The Auditor is offered `SWAP` only when alternative clusters exist. Regeneration prompts no longer show timeout or working directory. Decoding stays strict. A member inference template that sets `response_format` is 400 `ErrTribunalTemplateInvalid`, because the Gateway sets it per call.
- Tribunal consensus prompts now include the signed operator, session, case, investigation, and task context, and the typed action payload. `intent_data` is optional; its absence alone no longer makes an action unclear.
- Evaluation preflight now rejects shared Data and Inference Operator runtimes when Tribunal L2 is enforced by `consensus` or `notary`, before creating a run. Tribunal vote inference commits are not represented in the shared-runtime ledger bracket; use a dedicated outbound Inference Operator alongside the campaign's Data Operator. A signed Tribunal inference receipt rejected for insufficient L2 quorum is recorded as `policy_denial`, not a provider `internal_error`.
- A scored agent turn under `consensus` or `notary` no longer fails as `internal_error` because the observer rejected the BEGIN of an inference still waiting on its vote round. An inference is not voted, so its observation windows open right before publish. A Sage state change denied for insufficient L2 quorum carries the executing Operator's signed `L2_QUORUM_NOT_MET` rejection and is recorded as `policy_denial`.
- Strict evaluation preflight releases all requested Ollama model tags in one governed command and verifies the final provider process list inside that same L5 execution. It fails if any requested tag remains resident. Ollama acknowledges an unload before its runner stops, so the check re-reads `/api/ps` within the provider status timeout and fails only if a released tag is still resident when that timeout elapses. A failing model maintenance command's error now names the Operator's own error line.
- A held-context repetition whose previous repetition left no trace now records the execution failure class `held_context_unavailable` instead of `internal_error`.
- An assignment whose frozen scenario names a tool the agent catalog no longer has, such as `log_stream_filter`, now records the execution failure class `scenario_contract_invalid`. The result is an uncounted `INVALID_EVIDENCE`, and the run continues. Before, the run stopped and left the assignment `running`, so resume failed closed. `ztd eval runs repair <run>` now resolves such a stranded assignment when it left no agent trace, and holds the run lease for the whole repair.
- A run stopped by the first interrupt or an app stop request now releases as `waiting` when assignments remain queued, so it can resume. `ztd eval runs cancel` alone cancels the queued assignments and releases the run as `cancelled`.
- Observe producer rejections now return a typed body with a stable code; transition and stale-update details survive the Gateway response, while ownership and internal failures omit record or implementation details. The agent harness client preserves the rejection cause for error inspection.
- An untargeted inference dispatch or campaign Inference Operator selection no longer fails as ambiguous when a dedicated Inference Operator is enrolled beside the Gateway's embedded Operator. The dedicated Operator is preferred, and the embedded Operator serves only when no dedicated one is active.
- Scrubbing a JSON object or array now scrubs each scalar in place, so the result stays valid JSON with its key order unchanged. Before, a scrubbed `audit_receipt_list` result could carry a bare UEI token where JSON expects a value, and it no longer decoded.
- UEI tokens now name the runtime that minted them (`{{UEI_<owner>_N}}`), and L5 rehydrates only its own runtime's tokens. Before, tokens were numbered per runtime, so a token from another runtime either failed rehydration or, when the local runtime held the same number, resolved to an unrelated local secret. A Data Operator's token in a tool result now reaches the next turn on a dedicated Inference Operator as an opaque placeholder, so multi-turn tool workflows complete without any runtime's secret reaching the model provider. A foreign or ownerless token in any other action still fails closed with the signed `RECEIPT_FAILURE_CODE_REHYDRATION_FAILED`.
- The agent harness posts a consensus deliberation to the bound application over a client that authenticates the application by its Gateway-issued SPIFFE identity, like the Gateway's own deliberator. Both use `httpclient.SPIFFEServerTLSConfig`. Before, the harness verified the application's certificate by hostname, which it never carries, and presented its own Operator certificate.
- The CLI SSE client accepts a line up to twice the escaped size of both execution output streams. Before, an `approval.completed` event carrying a large tool result overflowed the line cap after the approved call had already executed, and the stream dropped.
- `tool-select-grep`, `tool-arg-grep-pattern` and `recovery-error-guided-retry` asked the model to search a directory with a tool that reads one file, so no correct answer existed. They now expect `search_directory`, and `recovery-error-guided-retry` shows the model the error the tool actually returns.
- Checking whether a run's dataset is already in the public mirror (`ztd eval runs publish`, publishing `resume`, and mirror reconcile) now makes one `GET /history?kind=catalog_snapshot&dataset=<id>&limit=1` request; the mirror filters on the server. Before, the check paged the whole retained history and failed with `history exceeds 3200 retained records` once the mirror held more catalog snapshots than that.
- The agent executor and trace verification now record a tool call's arguments through one typed request decode against the declared schema: a valid `run_shell_command` as its canonical `RunShellCommandRequest` JSON, anything else as canonical generic JSON. Verification rebuilds each tool's schema from the trace's signed declarations. Before, a `run_shell_command` call missing `command` was recorded in generic form but verified against a typed form, so a valid trace was imported as `INVALID_EVIDENCE`. `ztd eval runs repair <run> --regrade` re-imports each terminal result from its sealed agent trace and replaces only results whose lifecycle differs; the trace is never changed. Arguments that pass the schema but fail the typed decode are now a model-visible tool failure instead of a harness error, and Tribunal authoring rejects only a non-empty `hostnames`.
- An evaluation executor failure with no agent trace now verifies through the executor failure check. Before, verification failed with `agent trace is required for homogeneous verification`.
- The public feed read endpoints `/bootstrap`, `/snapshot`, `/proof-catalog`, `/proof-manifest` and `/proof-segments` gzip their responses when the client sends `Accept-Encoding: gzip`. Before, they were served uncompressed.
- An attended conformance run reports a typed `ConformanceApprovalRequest` (case, attempt, ingress, decision and, once it exists, the transaction hash) for each case that suspends, and `ztd test conformance-loop` answers each suspended transaction from its own case's request. Before, decisions were handed out in arrival order against a predicted plan, so under `ratify` an out-of-order suspension received another case's decision.

## Compatibility

The synthetic intent-only shell tool is removed, and new traces carry no string command step fields. `CandidateOutput.command` and `ReviewOutput.command` are kept only so v1.2.0 `agent-trace.v7` Tribunal steps still decode; an `agent-trace.v8` trace that sets them is rejected. Catalog digests change. Campaign import pins `agent-trace.v8`, so campaigns sealed earlier stay in history under their own release, and `ztd public verify-agent-trace` still verifies them. Campaigns and Tribunal traces recorded on the previous tool catalog remain in campaign history attributed to the release they measured. New campaigns freeze against the new catalog, and runtime execution provides no compatibility shim for the removed tool. Historical release notes retain their original scope.

Tribunal authors one executable with argv, executed without a shell. Pipelines, chaining, redirects, globs and substitutions are unavailable under this contract. Investigation baselines that assumed those compositions require reassessment; model compliance and score comparisons still require a scored campaign.

- `ztd auth enroll consensus` and `ztd auth consensus` are removed; use `ztd consensus enroll app|tribunal` and `ztd consensus status`.
- Gateways under consensus/notary now report `governance_ready=false` until the consensus is usable; health-gated automation should bind first.
- Runs started before this release froze no consensus binding and cannot be executed or resumed; they stay in history. Start a new run of the same campaign. Campaign specs that froze `governance_posture` keep their digest; the field is ignored.
- Outbound Operators must run v1.3.0. Under `consensus` or `notary`, an older Operator still requires L2 votes on inference, observations and read-only actions and rejects them for insufficient quorum. It also has no `OLLAMA_MODEL_RELEASE` handler.
- Outbound Operators receive consensus trust only at enrollment or certificate renewal. Restart running Operators after `ztd consensus enroll tribunal` or `enroll app`.
- An existing `ztd.db` is not rewritten. INV-STOR-SCHEMA-01 forbids `ALTER TABLE`, column back-fills, and a reader for the old `receipts` shape. Start Gateway and Operator runtimes from a new runtime root. Past `ztd.v1.operator.receipt.recorded` events already hold the canonical protojson body in `content_text`, but this release does not copy old `receipts` rows onto those events.
- The UEI token format changes from `{{UEI_N}}` to `{{UEI_<owner>_N}}`. Each runtime persists its owner under `uei_owner` in its token store. Ownerless tokens minted by earlier releases are not loaded and never resolve. They stay opaque in an inference prompt and fail closed in any other action. The new runtime root this release requires starts with no old tokens.
- Audit HTTP clients must call `/api/v1/audit/event-receipts` and read `event_receipts`, `event_receipts_count`, `event_receipts_summary`, and `event_receipts_total`. `ztd report all` consumers must read `event_receipts.csv`.
- The signed ActionReceipt payload, proto field numbers and JSON names, the chain event type `ztd.v1.operator.receipt.recorded`, the pubsub channel prefix `receipts:`, the MCP tools `audit_receipt_list` and `audit_receipt_get`, and consensus votes are unchanged.
