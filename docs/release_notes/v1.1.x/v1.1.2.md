## [1.1.2] - 2026-10-16 - Evaluation Held Context, Conformance Targets, and Failure Receipt Integrity

### Overview

v1.1.2 is a patch release on top of v1.1.1. Evaluation campaigns support held context across repetitions (`EvaluationCampaignSpec.hold_context = 13`), allowing multi-repetition runs to continue investigations in the same workspace with chained conversation history. Conformance test suites introduce target selection and explicit unavailable-coverage semantics (`NOT_RUN_OUTBOUND`, `NOT_RUN_A2A`) with `UNAVAILABLE` case verdicts and `INCOMPLETE` suite verdicts. Platform governance and execution error handling now guarantee that action handler errors propagate through L5 to produce authoritative signed `FAILED` terminal receipts, eliminating silent completion of failed operations. The egress scrubber adds single-pass rehydration without rescanning and streaming safety boundaries. Platform logging features component tagging, stdlib HTTP `ErrorLog` integration, and cross-platform socket disconnect classification for both Unix and Windows. Model capability observations in evaluation rollouts are now strictly diagnostic, ensuring every selected model receives governed tool declarations without intake exclusion. Evaluation Explorer brings a refreshed UX with compact Live stream indicators, direct links to failure diagnostics, and a dedicated About view.

All wire changes are strictly additive and backward compatible with v1.1.1 artifacts.

### Highlights

* **Evaluation campaign held context across repetitions** — Multi-repetition campaign cells can now preserve investigation context (`hold_context: true`). Subsequent repetitions receive the prior repetition's conversation history and execute in the same scenario workspace while preserving cell-level isolation.
* **Conformance targets and unavailable coverage** — Conformance runners support explicit target and enrollment-based root discovery. Missing optional infrastructure (such as an outbound Data Operator or harness A2A downstream) records `NOT_RUN_OUTBOUND` or `NOT_RUN_A2A` observations, verifies as `UNAVAILABLE`, and yields an `INCOMPLETE` suite verdict without hiding required coverage.
* **Authoritative signed failure receipts** — Removed `fireAndForgetActionHandler`, returning synchronous `(string, error)` across all governed handlers. Execution failures (missing files, command non-zero exits, mutation errors) produce signed `FAILED` receipts (`RECEIPT_FAILURE_CODE_EXECUTION_FAILED`) with preserved typed error causes.
* **Scrubbing single-pass rehydration** — Rehydration replaces tokens in a single pass without rescanning restored text, preventing substitution loops. Streaming inference requires an active egress scrubber before provider dispatch.
* **Cross-platform disconnect classification and server logging** — Gateway and Operator servers inject structured platform loggers into stdlib `http.Server.ErrorLog`. Client disconnects (`EPIPE`, `ECONNRESET`, and Windows Winsock codes `WSAECONNRESET`, `WSAECONNABORTED`) are classified without string matching and logged at `DEBUG`, keeping `ERROR` logs reserved for genuine faults.
* **Diagnostic model capabilities and provider failure reasons** — Model capability observations (tool calling, structured output, thinking) are treated as diagnostic observations rather than intake filters. Rollout intake (`ztd eval rollout add`) never excludes models or suppresses tools based on unprobed capabilities; each evaluation dispatches tools and captures the current provider response. Failed provider dispatches generate clear public failure sentences (e.g., `capability_unsupported`, `context_overflow`, `backend_timeout`) and lead diagnostics without obscuring grade evidence.
* **Trace inspection CLI and Evaluation Explorer UX redesign** — Added `ztd eval runs trace` for offline inspection and verification of sealed agent traces. Evaluation Explorer delivers a redesigned Live view with compact status indicators, direct linking from failed assignments to full diagnostic detail sentences, event rendering for all runs in the selected release before summaries arrive, and a dedicated About view.

### Added

* **Protocol** — `EvaluationCampaignSpec.hold_context = 13` (`eval.proto`), `GovernedActionBinding.action_type = 10` (`eval.proto`), and `ConformanceObservationKind` values `CONFORMANCE_OBSERVATION_KIND_NOT_RUN_OUTBOUND = 7` and `CONFORMANCE_OBSERVATION_KIND_NOT_RUN_A2A = 8`.
* **CLI** — `ztd eval runs trace` command for inspecting sealed assignment agent traces by ID or `--scenario`, with optional `--full` rendering and JSON output (`internal/cli/cmd/eval/runs_trace.go`).
* **Held context** — `internal/services/evaluation/campaign_held_context.go` for managing conversation history, workspace continuity, and harness failure detection when topologies change across repetitions.
* **Socket error classification** — `internal/services/logging/socket_errors_unix.go` and `internal/services/logging/socket_errors_windows.go` implementing platform-specific socket error unwrapping (`WSAECONNRESET`, `WSAECONNABORTED`, `WSAECONNREFUSED`).
* **Constants** — `ErrActionExecutionFailed`, `ErrEvaluationHeldContextUnavailable`.
* **Explorer About View** — Dedicated About view presenting the Explorer as a live window into ztd development and evaluation methodology (`evaluation-explorer/src/views/AboutView.tsx`).

### Changed

* **Governed action execution** — All 14 action registrations in `internal/services/pubsub/pubsub_commands.go` now return synchronous `(string, error)` results. Non-completed execution results fail closed at L5.
* **File operation error propagation** — `HandleFsReadRequest`, `HandleFileEditRequest`, `finishLedgerTwoPhaseCommit`, and `storage.HistoryHandler` preserve and join underlying error causes in the returned error chain.
* **Server error logging** — Gateway HTTP/HTTPS, public mirror, and explorer `http.Server` instances use `slog.NewLogLogger` backed by the injected platform logger, tagging records with `component: gateway` or `component: operator`.
* **Inference diagnostics** — Non-streaming and streaming inference failure logs record `failure_code`, `provider_attempt_id`, `transaction_id`, and `logging.ErrorKind` without leaking prompt or provider payload text.
* **Rollout capability handling** — `ztd eval rollout add` never excludes models based on saved capability probes; every evaluation sends tools to the provider and records current responses.
* **Provider failure diagnostic output** — `AssignmentOutcomeSummary` and scenario grading format provider dispatch failures with fixed public category reasons instead of attributing missing responses to model behavior.
* **Tool schema validation** — `file_write_on_operator` requires `minLength: 1` on `content` and validates content before governed dispatch.

### Removed

* **`fireAndForgetActionHandler`** — Removed from `internal/services/pubsub/pubsub_commands.go`; all actions require explicit outcome and error return.
* **Obsolete enrollment CLI paths** — Removed unused legacy enrollment helpers and posture constructors.
* **`WhatAmILookingAt` banner** — Removed from Evaluation Explorer Live view to maximize event stream visibility.

### Fixed

* **Silent success on failed filesystem reads** — Read failures previously returned nil to L5, generating `COMPLETED` receipts despite exit code 1. All failed reads now receive signed `FAILED` receipts.
* **Normal shutdown logged as failure** — Normal `SIGTERM` shutdown of Gateway listeners emitted `http: Server closed` at `ERROR` level. `GatewayModeService.Start` now handles `http.ErrServerClosed` as normal listener completion while preserving genuine startup causes.
* **Disconnected mirror clients** — Broken pipe and connection reset errors during mirror responses are now recognized as client disconnects and logged at `DEBUG`.
* **Explorer live stream noise and navigation** — Filtered transient live events, improved Recent runs links, and linked failed assignment rows directly to Assignment Details.
