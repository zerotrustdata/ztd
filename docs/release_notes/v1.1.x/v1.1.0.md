## [1.1.0] - 2026-10-14 - Governance Conformance and Signed Rejection Evidence

### Overview

v1.1.0 is a minor release on top of v1.0.6. Every governed ingress now returns typed, Operator-signed evidence for a rejection or refusal, not just for success. A new governance conformance suite drives a case catalogue over every ingress and posture, grades each case from that signed evidence alone, and verifies the sealed record offline. Tier-qualification campaigns carry the signed receipt of every governed tool call and reject unverifiable evidence. Runtime scratch moves under `.ztd/`. The plaintext master key file is removed.

The release adds wire contracts and removes CLI surface (`ztd eval boundary`, `--master-key-file`), so it is a minor bump. See Removed for the upgrade path.

### Highlights

* **Signed rejection evidence on every ingress** — Direct envelope submission, governed dispatch, MCP and A2A return a typed `GovernanceRejection` carrying the executing Operator's signed rejection receipt, or a typed `IngressRefusal` for pre-envelope refusals. A denied L3 approval is now a signed `L3_DENIED` rejection too.
* **Governance conformance suite** — `ztd eval conformance run | verify | report` runs `governance-conformance@1.0.0` against a live native stack, seals the record with a digest sidecar, and re-derives every verdict offline.
* **Evidence-first campaigns** — `agent-trace.v2` keeps each governed tool call's signed receipt, the Data Operator's ledger bracket is verified on import, and unverifiable evidence grades `INVALID_EVIDENCE`.
* **Fail-closed key custody** — The plaintext `--master-key-file` path is gone. Hosts without an OS key store seal under ssh-agent or fail closed.
* **Windows one-command onboarding** — `irm https://zerotrustdata.io/start.ps1 | iex`.

### Added

* **Typed governance outcomes on every ingress** — `GovernanceRejection` (with the Operator-signed rejection receipt and its `rejection_code`), `IngressRefusal` (pre-envelope refusals, including MCP and A2A `error.data`), the full signed `ActionReceipt` on governed dispatch, MCP `tools/call` and A2A `a2a/call`, and one typed `GovernedSuspension` for a suspended call. `ztd operator run` prints the transaction ID and rejection code.
* **Signed L3 deny** — `L3Metadata.denied` (outside the transaction hash) and `GOVERNANCE_REJECTION_CODE_L3_DENIED`. A denied approval resubmits the suspended envelope with the deny marker. L4 rejects it in every posture with `ErrTxL3Denied` and keeps the nonce spent, and L5 signs the rejection on the executing runtime. `POST /api/v1/approvals/respond` with `approved: false` returns that receipt, and `approval.completed` carries it to every consumer: `ztd auth approve` fails with `ErrTxL3Denied`, the TUI reports "denied", and the console has a Deny button.
* **Governance conformance suite** — `ztd eval conformance run`, `verify` and `report`. `governance-conformance@1.0.0` drives a 26-row case catalogue over direct, dispatch, CLI, MCP and A2A ingresses in every posture, and grades each case from the Operator's signed evidence (oracle, canary manifest, commitment-ledger bracket). The run is sealed as a `ConformanceRunRecord` with a digest sidecar. `verify` recomputes every verdict offline, and any changed byte is `INVALID_EVIDENCE`. `report` builds a case-by-posture coverage table and an L1 doctrine recall report. The doctrine adversarial corpus is an embedded package.
* **Conformance protocol** — `protocol/proto/ztd/eval/v1/eval.proto` adds `ConformanceRunRecord`, `ConformanceCaseEvidence`, `ConformanceObservation`, `ConformanceVerdict(Set)`, `ConformanceFailureClass`, `ConformanceSuiteVerdict`, `CanaryManifest`, `ConformanceAnchor`, `EVALUATION_SCENARIO_CATEGORY_CONTAINMENT` and `EVALUATION_ASSIGNMENT_LIFECYCLE_STATUS_INVALID_EVIDENCE`. Go and TypeScript bindings are regenerated.
* **Agent SUT groundwork** — Canonical SUT contract vectors, the SUT client, per-persona graders, the secondary judge, and three seeded-investigation scenarios under `eval/investigations`. Live runs wait on an external SUT.
* **Ephemeral ssh-agent for multi-process harnesses** — `ztd test scale` and `ztd test release-smoke` run a private in-process ssh-agent under the run Gateway's `.ztd/agent/` (`keystore.EphemeralAgent`, Linux). Children seal under it without touching the host keyring.
* **Runtime scratch API** — `RuntimeFileService.MkdirTemp` creates scratch under `.ztd/tmp/`, and `ssh.MkdirRemoteScratch` stages remote uploads under `<login>/.ztd/tmp`. INV-FS-11 documents both.
* **Windows one-command onboarding** — `website/static/start.ps1` installs, starts a Gateway, signs in, and runs a first governed action. The homepage quick start and Releases pages list it.

### Changed

* **Receipt trust** — Receipts verify only against the key bound to the executing Operator at enrollment. A self-declared signer key ID is no longer trusted.
* **Direct envelope submission** — Binds `requestor_user_id` and `acting_app_id` to the authenticated identity. Returns 503 instead of 500 when the verifier cannot run, renders pre-L4 refusals as sentinels only, and returns its 200 receipt as canonical protojson (enums by name) instead of `encoding/json`.
* **Governed dispatch** — Runs L1 doctrine before the L3 gate, renders only typed sentinels, and returns 404 for an unresolved target session.
* **Pipeline classification** — An event/action mismatch is a signed L4 rejection, a forged L2 vote rejects as `L2_SIGNATURE_INVALID`, and L5 receipts copy the Warden's L2/L3 status.
* **A2A** — Suspends only on a missing L3 proof, like MCP. The agent harness A2A client posts to `/api/v1/a2a/call`.
* **Approval waits** — The CLI, harness and attended flows open the SSE stream before submitting, so an early approval is no longer lost.
* **MCP `tools/list`** — Returns native tools alongside a downstream MCP server's tools.
* **Campaign traces (breaking)** — Traces are `agent-trace.v2`, and every governed tool call keeps its signed receipt. Import verifies the Data Operator's ledger bracket, and unverifiable evidence is `INVALID_EVIDENCE` with no grades.
* **`run_commands_with_operator`** — Executes the command the model wrote in `command`. The second command-generation inference is removed.
* **Empty model replies** — An empty completion is a receipted empty `InferenceResult` and grades `FAIL` against the model instead of `provider_response_invalid` (INV-EVAL-CAMP-34).
* **Compliance** — Admits native eval runs only from a verified conformance record.
* **Data Operator binding** — `ValidateAgentDataOperator` accepts only a direct child of `<project>/.ztd/operators` (INV-EVAL-CAMP-32). `operator deploy --local` without `--hosts`/`--dest-dir` deploys numbered `op-NNNNN` dirs there.
* **Throwaway Operator trees** — `.ztd/operators/<name>/…` is agent-editable. The operators dir, `<name>` itself and the nested `.ztd/` stay protected.
* **Port resolution** — `config.LoadGateway` only validates. `gw start` resolves free ports (`config.ResolveGatewayPorts`).
* **Scratch locations** — The system trust installer, assignment audit, agent verify, compliance bundle verifier, chaos targets, remote stream/deploy staging and the release-smoke default root (`.ztd/tmp/release-smoke-<UTC ts>`) all use `.ztd/` scratch. The Makefile no longer sets `TMPDIR`.
* **Headless onboarding** — `start.sh` tells a host with no OS key store to start an ssh-agent with a key loaded. CI onboarding and the website live smoke run under an ephemeral ssh-agent.

### Removed

* **`--master-key-file` / `ZTD_MASTER_KEY_FILE` (breaking)** — The plaintext master key file is removed from `gw start`, `operator start`, `operator deploy`, vault, report, compliance, public and the root command, along with `ZTD_E2E_MASTER_KEY_FILE` and the launch-profile field. Hosts without an OS key store (Secret Service, Keychain, Windows Credential Manager) now seal under ssh-agent (an Ed25519 or RSA key reachable through `SSH_AUTH_SOCK`) or fail closed.
  - **Upgrade:** a Gateway started on v1.0.x with `--master-key-file` has `master_key_file` in its launch profile and fails closed on restart with `ErrLaunchProfileCorrupted`. Its vault was sealed under the file. Load the host's key source (on Linux without Secret Service, `eval "$(ssh-agent)" && ssh-add`), then run `./ztd gw clean --yes`, `./ztd gw start` with the old startup flags, and `./ztd login`. `gw clean` keeps the old runtime as `.ztd-<MMDDHHMM>`. See [Upgrading a v1.0.x Gateway](../../architecture/encryption.md#upgrading-a-v10x-gateway).
* **`ztd eval boundary`** and the **`core-execution-boundary`** suite — replaced by `ztd eval conformance`.
* **Second command-generation inference** in `run_commands_with_operator`, and `CommandForbiddenTerms`.
* **`PathTmp`** and all `/tmp`, `$HOME` and `%TEMP%` scratch in code, tests, the Makefile and remote staging.
* **Dead Windows certificate import** (`internal/cli/auth/windows_crypto*.go`).

### Fixed

* **L3 deny left no evidence** — A denied L3 suspension on MCP and A2A wrote no signed receipt. It is now a signed `L3_DENIED` rejection (see Added).
* **Early approval lost** — An approval that arrived before the waiter subscribed was dropped. Waiters now subscribe first.
* **Throwaway Operators could not edit their own tree** — `security.IsProtectedRuntimePath` rejected every `.ztd` path component, including `.ztd/operators/<name>/…`.
* **Campaign mirror misclassification** — `CampaignMirrorReconciler` treated a run with no verification report as failed instead of ineligible, because it checked `fs.ErrNotExist` where `RuntimeFileService` returns `constants.ErrNotFound`.
* **Config loading probed ports** — `config.LoadGateway` opened sockets while loading configuration.
* **Model-provenance preflight test race** — The fake Gateway in `TestPreflightModelProvenanceContext_SSEReadyBeforeDispatch` signalled readiness after flushing SSE headers. It now mirrors the real Gateway's order.

### Tests

* The Tier 1 socket check follows helpers transitively to dials and listeners, and its seeds cover `tls.Listen/Dial/DialWithDialer`, `http.Serve/ServeTLS`, and the `net.Dialer`, `net.ListenConfig`, `tls.Dialer`, `http.Server` and `httptest.Server` methods. Every test it flagged moved to a same-package integration file.
* `testutil.TempDir` is project-local (`<module>/.ztd/tmp/tNNN`), and `testutil.OperatorDir` gives agent-editable Operator roots. forbidigo rejects `os.TempDir` and `t.TempDir`, and `make lint` rejects empty-dir `os.MkdirTemp("")`/`os.CreateTemp("")`.
* In-process tests use memory keyrings. `ephemeral_agent_linux_integration_test.go` covers the ephemeral ssh-agent.
