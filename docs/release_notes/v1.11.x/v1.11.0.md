## [1.11.0] - 2026-11-19 - Hosted Inference Providers, Fleet Harness, and Rollout Recovery

## Overview

This release lets an Inference Operator serve hosted model providers beside its local provider. A governed inference request names a hosted provider class, and the Inference Operator signs an attestation of that hosted egress. Every hosted model is bound to a model identity digest that is re-checked on each call, so a model the provider re-versioned or rerouted fails a pinned evaluation instead of being graded silently.

Transient provider failures are retried. A provider that asks for a later retry, such as a rate limit or an overload, is retried under a bounded policy with fixed waits. Each superseded attempt stays in the evidence.

Evaluation runs can address a fleet of Data Operators. The model reads a frozen roster, names the targets of each tool call, and every target runs its own governed pass and signs its own receipt. A DevOps fleet suite measures that work, and an Operator can be deployed mid-run and join the roster.

Rollout recovery is corrected. A long rollout no longer fails when the ssh-agent key that opens the evidence vault expires partway through, and each failure that a rollout records now names its class.

## Added

- Hosted inference providers.
  - An Inference Operator (the `inference` capability) serves the hosted provider classes `gemini`, `anthropic`, and `openai` beside its one local provider, `ollama` or `llamacpp`. The local provider is not replaced.
  - A class is served only when its API key is set in the Operator's process environment or `.env` at startup: `GEMINI_API_KEY`, `ANTHROPIC_API_KEY`, or `OPENAI_API_KEY`.
  - A key that is set but blank, whitespace-only, or contains a CR or LF fails Operator startup with `ErrInferenceHostedProviderKeyInvalid`.
  - Discovered classes are advertised as `inference_hosted_providers` in the Operator runtime config and bound at enrollment approval. The clients are `GeminiBackend`, `AnthropicBackend`, and `OpenAIBackend`.
  - Each hosted client refuses any origin other than its fixed API origin before it sends credentials, refuses HTTP redirects, and performs no client-side retries.
  - A governed inference request names its hosted class in `provider_class` on `InferenceRequested`. An empty value selects the local provider. A hosted class is the envelope's explicit consent to hosted egress.
- Hosted model identity.
  - The identity digest is the SHA-256 of `ztd.hosted-model-identity.v1` followed by a newline and the canonical JSON of `provider_class`, `provider_origin`, `model`, and `provider_model_version`. It is computed by `models.ComputeHostedModelIdentityDigest`.
  - `provider_model_version` is read again before every call: the Gemini `version`, the Anthropic `created_at`, or the OpenAI `created` field.
  - A pinned call fails with `ErrInferenceModelDigestMismatch` when the provider re-versioned or rerouted the model.
- Hosted egress attestation. The Inference Operator signs an `InferenceHostedEgressAttestation` inside `InferenceResult`. The attestation is covered by `result_digest` and records the provider origin and class, the requested model, the served model version, the provider model version, the identity digest, the provider response ID, and the raw response digest and size. `models.ValidateHostedEgress` checks it on the Inference Operator and in Gateway dispatch.
- Hosted model provenance.
  - A hosted attempt sends no Observer or Provenance BEGIN or FINALIZE. The Gateway records a `ModelProvenanceAttestationWindow` with the status `MODEL_MANIFEST_VERIFICATION_STATUS_HOSTED_PROVIDER_REPORTED` and a `hosted` block (`HostedModelAttestation`).
  - `digest_match` is true only when the expected digest is non-empty, equals the identity digest, and the served model equals the requested model.
  - Campaign verification, `--require-provenance`, and strict policy treat a hosted window like any other window. A hosted-only campaign does not require an Observer Operator.
- Opaque provider state carried verbatim.
  - Gemini thought signatures are carried as `provider_signature` on each tool call. They are recorded in the agent trace and returned on continuation turns.
  - Anthropic `thinking` and `redacted_thinking` blocks and OpenAI encrypted reasoning items are carried as `InferenceProviderReasoning`: the provider class and the canonical JSON item. The item is returned only to the same provider class and is bounded at 256 KiB. It contains no readable text, the scrubber never reads it, and the result digest covers it.
- Hosted evaluation commands.
  - `ztd eval models add <model> --provider <class>` registers a hosted model at the identity that the Inference Operator's live inventory reports. A `--digest` that disagrees with that identity fails.
  - `ztd eval gates probe <model> --provider <class>` probes one hosted model, and `ztd eval gates inference --provider <class>` runs the inference acceptance matrix against one. Omit `--provider` for the local provider.
  - `ztd eval models freeze` keeps hosted models in the registry re-resolved at their current digest. It never bulk-freezes a vendor catalog. It fails with `ErrInferenceModelNotFound` when the provider no longer lists a model.
  - `ztd eval models diff` shows a hosted entry only when the catalog or the registry names it.
- Hosted formations. `ztd eval formations create --<role>-provider-class` accepts the hosted classes. `--<role>-trust` defaults from the class: `sovereign` for a local provider and `delegated` for a hosted one. A delegated role must be on a hosted class. One Inference Operator can run a formation that mixes local and hosted models.
- Every evaluation inference path sets the request's provider class from the model variant. The paths are the judge, Tribunal, agent executor, tool-calling probe, and capability probe.
- Hosted Tribunal consensus.
  - `ztd consensus enroll tribunal --model` resolves the tag through the frozen model registry, local or hosted.
  - The binding pins the registry digest and, for a hosted model, its provider class in the new `consensus_model_provider_class` field on `PlatformEnrollmentGovernancePayload`.
  - The Inference Operator re-verifies the pinned hosted identity digest on every vote. A hosted vote model sends each member's scrubbed vote prompt to that provider.
  - Evaluation runs freeze the hosted provider class in `EvaluationConsensusIdentity.model_provider_class`.
- Agent hosted-class checks. `ztd mcp agent verify <agent>` and `ztd mcp agent show <agent>`, with `--json`, report whether an active Gateway Inference Operator serves the agent's matching hosted class and which models of that class are in the frozen evaluation registry. The mapping is `claude` to `anthropic`, `codex` to `openai`, and `gemini` to `gemini`. When the CLI is not enrolled or the Gateway is unreachable, both commands report the Gateway status as unavailable and still complete.
- Console. The Operator inventory shows the hosted providers each Operator advertises.
- Transient inference retries.
  - New `RECEIPT_FAILURE_CODE_BACKEND_TRANSIENT` and `INFERENCE_DISPATCH_FAILURE_CODE_BACKEND_TRANSIENT` mark a provider that asked for a later retry: HTTP 429, 500, 502, 503, or 529, or the provider's rate-limit or overload error. Authentication, permission, and billing failures remain `BACKEND_UNAVAILABLE`. The error is `ErrInferenceBackendTransient`.
  - Only a signed `FAILED` receipt with that code starts a retry, as decided by `governance.IsTransientFailureReceipt`.
  - The `TransientRetry` policy waits 5 seconds, then 20 seconds, then 40 seconds, and makes at most three retries.
  - Each retry is a new provider attempt with the next `retry_count` and a `retry_of` value naming the attempt it supersedes. A result whose `retry_count` differs from the dispatched one fails with `ErrIdentityBindingFailed`.
  - Clients never retry internally.
  - The policy applies to campaign agent turns and the Interrogator, evaluation judges, Tribunal intent member calls, and L2 Tribunal consensus votes.
  - Superseded attempts stay as evidence. They appear as `superseded_attempts` on `ConsensusVoteInference`, in Tribunal call records, and in judge `GraderModelCallRecord` values. The vote or judgment is the final attempt's.
  - A retried vote's `ztd.v1.consensus.vote.recorded` record names its final attempt and carries `retry_count`.
  - New `EVALUATION_CALL_CLASSIFICATION_RETRIED` marks a scored-chain attempt that a later attempt of the same call superseded. The attempt stays as evidence, and metrics skip it.
- Fleet harness.
  - The harness roster is the frozen, ordered set of Data Operators one run addresses. `ztd eval runs start --data-operators` selects the roster by Operator ID in roster order, or `all` for every active Data Operator. Each selected Operator is bound to the CLI session unless `--no-auto-bind` is set.
  - The model reads the roster in an `<operator_roster>` block. Each member's workspace is its own. Relative paths, and the working directory of `run_shell_command`, resolve inside the workspace of the Operator that runs the call.
  - `target_operators` on a tool call names its targets: roster indexes, Operator IDs, hostnames, or `["all"]`. The call runs once on each target as one governed action per target. Each target runs its own L1–L5 pass and signs its own receipt. Resolution happens once in the harness, so the verifier recomputes the same fan-out from the signed model request.
  - A `{{workspace}}` token in a scenario renders as `.`, the relative root that each target resolves against.
  - `devops-fleet@1.1.0`, in category `FLEET_OPERATIONS`, is a built-in suite of five scenarios: `fleet-config-rollout`, `fleet-subset-feature-flag`, `fleet-drift-repair`, `fleet-log-error-sweep`, and `fleet-deploy-then-use`. Each needs a roster of three Data Operators, and gold file states are checked on every Operator.
  - `OPERATOR_DEPLOY` (`ActionTypeOperatorDeploy`) is a governed action. Its events are `ztd.v1.operator.deploy.requested`, `ztd.v1.operator.deploy.completed`, and `ztd.v1.operator.deploy.failed`. The `operatordeploy` package holds the staging, start, and watch logic. `ztd operator deploy` and the Gateway's dispatch of `OPERATOR_DEPLOY` both use it.
  - An Operator deployed by an executed `operator_deploy` tool call (`MCPToolOperatorDeploy`) joins the roster mid-run. The deploy joiner watches the launch over the CLI's SSE stream and binds the new Operator's session to the CLI session. The harness then appends a `<operator_roster_update>` block to the conversation and records an `AgentTraceRosterJoin` in the trace.
  - `agent-trace.v14`. The trace advances to this version and carries `target_operators` on each tool call, the frozen `roster`, and `roster_joins`. Campaign assignment verification accepts `agent-trace.v14`.
- Swagger. The Gateway OpenAPI document (`swagger.json` and `swagger.yaml`) documents `OPERATOR_DEPLOY` and the three `ztd.v1.operator.deploy.*` events.

## Changed

- Built-in suites are `default-suite@1.37.0`, `smoke-suite@1.35.0`, `investigations@1.31.0`, `quickstart@1.5.0`, and `devops-fleet@1.1.0`.
- The checked-in suites are `consensus-screen@1.13.0`, `consensus-evidence@1.13.0`, `consensus-safety@1.11.0`, and `prompt-injection-resilience@1.2.0`.
- The persona versions are Marshal `1.3.0` and Auditor `1.3.0`. The Marshal always includes a `feedback` field, which is empty unless its risk is `HIGH`. The Auditor answers one root object: `verdict`, `rationale`, `revised_arguments` (authored arguments, or `null`), and `swap_to_cluster` when the voting mode allows a swap.
- Every response schema the Inference Operator sends uses one subset that every provider applies, checked by `models.ValidatePortableResponseSchema`.
  - Tribunal authored arguments no longer declare `minLength`. Local grammars no longer force a non-empty command or summary. The decoders still reject an empty one.
  - The Triage classification response schema no longer requires a non-empty `intent_summary`.
  - Tribunal member calls carry a JSON response format whose schema is exactly what the strict decoder accepts.
- OpenAI function tools are sent with `strict: false`. The `text.format` response schema stays strict.
- Hosted usage is validated before the Inference Operator signs a result. An OpenAI `total_tokens` that disagrees with input plus output, or Gemini cached tokens above prompt tokens, fails the attempt with `ErrInferenceProviderResponseInvalid`.
- A phase whose models are all hosted, including a hosted judge, reads and releases no local residency. The end-of-run residency release runs only when the campaign dispatches a local model, so a hosted-only campaign does not need a reachable local provider.
- `ztd eval models add --provider <hosted>` scopes its inventory request to that class. A named class the Operator does not serve fails with `ErrInferenceOperatorNotCapable`.
- Scenario grader counts only scored model calls. A retried attempt is not counted as a second model call.
- `ztd eval runs repair <run>` also rewrites a run record that carries the retired campaign binding field. See Fixed and Compatibility.
- The staging logic of `ztd operator deploy` moved into the `operatordeploy` service. The command's flags are unchanged.
- On Linux, `gw start` and `gw restart` key recovery loads the vault's sealing SSH key into the ssh-agent for 24 hours, up from 8 hours (`ssh-add -t 24h`). An evaluation rollout reopens the vault from the agent for each campaign, so a key that expired partway through a long rollout failed every remaining campaign with `internal_error`.
- The base model inventory and the formation catalog overlay in `eval/` are pruned.
- Go dependencies are updated: `github.com/aws/aws-sdk-go-v2` v1.48.0, `golang.org/x/crypto` v0.59.0, `golang.org/x/sys` v0.50.0, `github.com/ebitengine/purego` v0.11.3, and `github.com/spf13/pflag` v1.1.0 (`go.mod`, `vendor/`).

## Fixed

- An evaluation rollout no longer fails the rest of its steps when the ssh-agent key expires.
  - A `ztd eval` process opens the evidence vault once per runtime root and holds it until the process exits. A failed open is not held, so the next read asks the key store again.
  - Within one process, the CLI key is unsealed once per identity and reused while the certificate on disk is unchanged. A changed certificate is unsealed again, and an expired one is refused.
  - A command started after the key expires still fails closed.
- Rollout failure classes name the cause.
  - `publication_failed` records a run whose results were persisted but whose public mirror publication failed (`ErrEvaluationPublicationFailed`). Such a run needs `ztd eval runs publish`, not a rerun. The class applies only when every failure in the error is a publication failure. A verification failure joined beside it keeps its own class.
  - `key_store_unavailable` records a run that could not unseal its CLI key or open its evidence vault because the key store is locked or does not hold the key.
  - Failures recorded before this release keep `internal_error`.
- A credited retry wait no longer expires the call that spent it.
  - A Gateway retry wait credited to the scenario budget mid-call, such as one fanned-out Tribunal target's vote retry, also moves the in-flight call's context deadline. The next target is not expired by that wait. The move is refused past the parent deadline, as the budget credit is.
- An L2 vote retry leaves the envelope lifetime that later stages need.
  - A vote retry wait starts only when it ends before `expires_at` minus `DispatchTimeout` and the share the later stages need: `ApprovalRequestTTL` (2 min) for the L3 wait, and 60 s for the Tribunal admission review.
  - Under `notary`, an exhausted vote chain ends as a vote failure rather than the admission review ending `AUDIT_FAILED`.
- A run record written before `4159dbb3` carries the retired campaign binding field `data_operator_session_id`. Such a record failed to load with `unknown field`, which failed `ztd eval runs list` and the `ztd public status` feed drift check for the whole runtime root.
  - The loader returns `ErrEvaluationRunRetiredBindingField`, naming the run. `ztd eval runs list` names every such run in one error.
  - `ztd eval runs repair <run>` removes only that field and saves the rest of the record unchanged. A record with any other unknown content is not rewritten. The `--json` output reports `binding_rewritten`.
- The Explorer Leaderboard role-leaders panel and formation table are corrected for hosted models.
- Tribunal consensus readiness checks the vote route.
  - A Tribunal member is ready only when its signer is enabled, its key is present, and its vote resolves to an active Inference Operator that serves the binding's model provider: the hosted class, or the local provider for an empty class. The selection is the one the vote dispatch uses.
  - The readiness check returns the reason a binding is not ready. The closed reasons are `member_owner`, `vote_operator`, `vote_operator_ambiguous`, and `signers`.
  - `/health` carries `consensus.not_ready` with those reason codes. `ztd consensus status` prints a `Not ready` line with the reason, and `--json` carries `not_ready`. `ztd gw status` and the TUI append the reason to `NOT READY:`.
- Explorer Leaderboard formations are ranked three ways.
  - Overall ranks every formation size-free, on the same score as the model Overall.
  - Self-hosted (size-adjusted) ranks all-local formations only. Their scores are unchanged.
  - Remote-hosted ranks the formations with a hosted member, normalized among themselves.
  - Hosted-member formations are no longer listed unranked.
- A named rollout checks every remaining campaign's recorded platform release before it runs any step. Previously, after a platform upgrade, each campaign frozen under the earlier release recorded a failed attempt, classified `internal_error`, and the rollout went on to the next. `runs start --dry-run` reports the same mismatch, and the failure class is now `invalid_input`.

## Compatibility

Every protocol change is additive: new fields and new enum values only, except that `ModelCampaignBinding` reserves field 7 (`data_operator_session_id`) and adds `data_roster` (field 8). The main additions are `InferenceRequested.provider_class`, `InferenceProviderReasoning`, `PlatformEnrollmentGovernancePayload.consensus_model_provider_class`, `EvaluationConsensusIdentity.model_provider_class`, `ModelProvenanceAttestationWindow.hosted`, `OllamaModelInventoryRequested.provider_classes`, the `retry_count` and `superseded_attempts` fields, `RECEIPT_FAILURE_CODE_BACKEND_TRANSIENT`, `INFERENCE_DISPATCH_FAILURE_CODE_BACKEND_TRANSIENT`, `EVALUATION_CALL_CLASSIFICATION_RETRIED`, `MODEL_MANIFEST_VERIFICATION_STATUS_HOSTED_PROVIDER_REPORTED`, `OPERATOR_DEPLOY`, and the `ztd.v1.operator.deploy.*` events. Consumers that switch on these enums will see the new values.

Run records written before `4159dbb3` must be repaired before they load. Run `ztd eval runs list`, which names each run it cannot read, then run `ztd eval runs repair <run>` for each one until `runs list` and `ztd public status` pass. Repair removes the retired field without translating it into `data_roster`, so such a run may no longer verify. Archived runs are not repaired, so `ztd eval runs list --archived` still fails on an archived run recorded before `4159dbb3`.

Campaigns frozen under another platform release do not start. Start, dry run, and resume refuse them with `ErrEvaluationPlatformReleaseMismatch`. Campaigns frozen against an earlier persona set refuse start, dry run, and resume with `ErrPersonaDigestMismatch`, and their existing runs, sealed traces, and stored grades still verify against their recorded prompts. The persona set digest is `63ada0005bacb1971a6e29ffc29bd778b3cc743cb5ab9a4b7d4aaeb2dfc04e24`.

The built-in and checked-in suites advanced because the roster block and `{{workspace}}` rendering changed every scenario's model input. Campaigns frozen under older suite versions must be recreated: for each registered checked-in suite, run `ztd eval suites update eval/suites/<id>.json`, then create new campaigns for the release being qualified.

Upgrade the Inference Operators that serve hosted classes to this release. Hosted providers require an Inference Operator started with the provider's API key. An older Operator advertises no hosted classes, so hosted requests never route to it. Transient retries require an Inference Operator on this release, because only that Operator signs `RECEIPT_FAILURE_CODE_BACKEND_TRANSIENT`. Against an older Operator, a transient provider failure remains a failure that is not retried.

Local inference between a Gateway and an Inference Operator on this release is unchanged for the local provider.

`/health` adds the `consensus.not_ready` field. It is additive and carries reason codes only. Consumers that do not read it are unaffected.

No CLI flag was removed. The ssh-agent key lifetime that `gw start` and `gw restart` key recovery uses changed from 8 hours to 24 hours. The new flags are `--provider` on `ztd eval gates probe` and `ztd eval gates inference`, which is omitted for the local provider, the hosted values accepted by `ztd eval models add --provider` and `ztd eval formations create --<role>-provider-class`, and `--data-operators` and `--no-auto-bind` on `ztd eval runs start`.

`agent-trace.v14` is new. Every new trace is sealed with it.

The Explorer view schema stays at 1.15.0.
