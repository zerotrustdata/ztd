## [1.10.1] - 2026-11-07 - Loaded Context Window and Repetition Stop

## Overview

This release replaces the fixed 16,384-token output cap with the context window the provider loaded the model with. It adds a separate stop for generations whose output degenerates into a loop. Each stop has its own typed outcome, so an assignment, a judgment, and the public feed say which one ended a generation.

Several evaluation failures that were reported in the wrong class now have their own:

- A judge that cannot decide a criterion no longer discards the model's work. The trace is persisted and the assignment is `GRADER_FAILED` with a typed cause.
- A request over the Inference Operator's size bound is reported as such, not as a generic receipt failure.
- A model's shell commands run only inside the attempt's own workspace.
- `tool-arg-grep-pattern` names the log marker its search pattern is graded against.

The Explorer view schema advances to 1.15.0 and the agent trace to `agent-trace.v12`. See Compatibility.

## Added

- A load step before each generation. The Ollama backend sends a load-only `/api/chat` request and reads the runner's `context_length` from `/api/ps`. The llama.cpp backend loads through `POST /models/load` and reads `n_ctx` from `/props`.
  - A model already resident with the requested `context_limit` is not reloaded and reports a zero load duration, so the attempt classifies `WARM`.
  - A provider that reports no window fails the generation with `ErrInferenceContextWindowUnavailable` before any prompt is sent.
  - The window is recorded on `InferenceResult.context_window`.
- A repetition stop in both backends. The backend watches the last 16 KiB of decoded text and thinking. It stops the generation once the output ends in one span repeated back to back at least four times over at least 4 KiB.
  - On a stop, it cancels the provider request, releases the scrubbed stream's held tail, and returns the output so far with finish reason `repetition` (`constants.InferenceFinishReasonRepetition`).
  - The thresholds are `constants.InferenceRepetition*`. A generation that never repeats is never stopped by them.
- Typed `repetition` outcomes:
  - `PUBLIC_FINISH_STATE_REPETITION` for the public finish state;
  - `JUDGE_FAILURE_REPETITION` for a judge;
  - `AGENT_FINISH_REASON_REPETITION` for an agent trace;
  - `EVALUATION_TRAJECTORY_OUTCOME_REPETITION` for a trajectory.
- `EVALUATION_TRAJECTORY_OUTCOME_NO_ANSWER`: an episode that ended with an empty final answer. A trajectory cannot pass without an answer.
- `model_summary.tool_calling_exclusions` in Explorer view schema 1.15.0: the number of the variant and role's assignments that the run's verified tool-calling probe excluded. It is always published, including zero.
- `RECEIPT_FAILURE_CODE_REQUEST_TOO_LARGE` and `INFERENCE_DISPATCH_FAILURE_CODE_REQUEST_TOO_LARGE`. The evaluation class is `request_too_large`.
- CLI certificate renewal. Gateway client commands renew the local CLI certificate before execution and during long-running commands, once the certificate passes two-thirds of its 7-day lifetime, the same point Operator leaves renew (`INV-AUTH-SESSION-09`).
  - It uses `POST /api/v1/auth/cli/renew` over mTLS. The renewed certificate names the same CLI session, user, and operator binding, and the session expiry moves forward with it.
  - The replaced certificate stays valid until it expires, so a running process that still holds it keeps working. The CLI L3 verifier accepts the most recent previous certificate while it remains valid. Logout and `--rotate-cli` revoke every certificate serial retained by the session, including older renewals.
  - Only the session's current certificate renews. The session update atomically checks the fingerprint and active status; logout and rotation re-read the certificate inventory after deactivation. Concurrent `ztd` processes serialize renewal on `.ztd/cli-identity.lock`, confined to the runtime root with symlinks refused.
  - A failed command-start renewal prints a warning, and the command still runs. Long-running commands retry transient failures with bounded backoff and stop their renewal loop when the command ends.
  - Local Gateway lifecycle, Operator startup and binary transfer, vault, report, compliance, test, version, and Swagger commands, plus local catalog and offline verification commands, skip renewal, as does `logout --local-only`.
  - CLI approval signing holds a shared identity lock through submission so its signature and TLS certificate remain consistent during renewal.
  - A lost renewal response requires explicit `ztd auth enroll user --rotate-cli` recovery. A Gateway without the route produces a rebuild-and-restart instruction.
- CLI certificate reinstatement. A CLI certificate that expired within the last 7 days is reissued for the same CLI session, user, and operator binding, with no passkey or human approval (`INV-AUTH-SESSION-10`).
  - Gateway client commands do this at start, so the next command after an expiry runs normally. `ztd login` and `ztd auth enroll user` do it before falling back to recovery.
  - It uses `POST /api/v1/auth/cli/reinstate` over server-authenticated TLS. An expired certificate cannot complete mTLS, so the request carries the expired certificate and a signature by its keystore-sealed key over a digest binding the CLI session and the new CSR. mTLS handshake verification is unchanged.
  - The Gateway requires the certificate to be signed by its Operator intermediate, unrevoked, no more than 7 days past expiry, and the session's current certificate, with the session and user active. A replay receives 412. A certificate expired longer, a logged-out session, or a revoked certificate still uses human-approved recovery.
- A catalog rule: every literal a model-authored tool argument is graded against must be visible to the model before it authors the argument. That means it appears in the prompt or seed, or in a non-decoy workspace file the scenario lets `read_file` open (`ErrEvaluationPromptUnanswerable`).

## Changed

- An omitted or zero `max_tokens` runs until the model stops or fills its loaded context window. A stated `max_tokens` larger than the window is the window. The Inference Operator no longer rejects `max_tokens` above 16,384, and the evaluation judge states no output limit.
- A model turn the Inference Operator stopped for repetition ends the episode as the model's answer (`INV-EVAL-CAMP-53`). Tool calls it emitted are not run. The assignment completes and grades `FAIL` with trajectory outcome `REPETITION`, and its output is not sent to the content judge.
- A content criterion the pinned judge fails to decide is recorded in the sealed trace as the last content judgment, with its `JudgeFailure` and no verdict (`INV-EVAL-CAMP-54`, `agent-trace.v12`). Previously the assignment was recorded as a traceless failure.
  - The assignment is `GRADER_FAILED`, with a fixed public reason for that failure.
  - The failed criterion's grade is `UNAVAILABLE` and binds no grader call.
  - The verifier re-derives a failure read from the judge's output from the signed result, so a decided verdict cannot be relabelled as a failure.
- A `run_shell_command` runs in the attempt's investigation workspace, or in a directory within it that the model names. A `working_dir` outside it, including the Operator directory that holds every other attempt's workspace, is refused before dispatch. This applies to both the direct and Tribunal paths.
- The agent system prompt names only the investigation workspace. It no longer prints the Operator's working directory.
- A `LABEL_MISMATCH` player grade names each mismatched label, for example `complexity simple, want complex`. A value outside the label vocabulary reads `unrecognized`.
- `tool-arg-grep-pattern` is `2.6.1`: its prompt names the `AUTH_FAILURE` marker. `default-suite` is `1.34.0`, and `consensus-evidence` is `1.10.0`.
- A trajectory failure reason says a tool was "hinted by the prompt" in both its private and public forms.
- `ztd auth enroll user` and `ztd login` no longer rotate a CLI certificate near expiry. Renewal keeps it current, and `--rotate-cli` is the only path that rotates the certificate and CLI session.
- CLI mTLS clients built by `auth.BuildMTLSClient` and `api.NewClient` read the CLI certificate from disk on each TLS handshake, so a renewal reaches a running `ztd mcp` or TUI. Evaluation harness CLI credentials use the same per-handshake source. Application credentials remain separately enrolled workload identities.
- The Operator and the CLI compute their renewal time with one helper, `certutil.RenewalTime`.
- The Explorer Leaderboard ranks a model in Primary and Assistant only when its summary publishes zero `tool_calling_exclusions`. A variant with an exclusion in any run is unranked in both roles. Lite requires no capability. Overall also requires the catalog's completion, structured JSON, thinking, and context window probes to pass.

## Fixed

- A judge reply that ran away to the old 16,384-token cap could not be decoded, and the assignment was recorded as a traceless `grader_failed` with the model's work discarded. A runaway judge is now stopped as `JUDGE_FAILURE_REPETITION`, and the trace persists.
- A turn whose tool output pushed the request past the Inference Operator's 256 KiB message bound failed as `RECEIPT_FAILED`, "Inference failed before a final response". It is now `request_too_large` and ends `FAILED`, never `PROVIDER_FAILED`.
- A model could list the Operator's `workspaces/` directory through `run_shell_command`'s `working_dir` and receive every attempt's fixture names.
- `tool-arg-grep-pattern` could not be passed. Its pattern was graded against `AUTH_FAILURE`, which the prompt never named and the case-sensitive search could not reveal.
- An empty final answer passed its trajectory as `DIRECT`.
- A model whose tool-calling probe failed could rank in the Primary and Assistant leaderboards on the accuracy of its text-only tasks. Its tool-bearing tasks were excluded as `invalid_evidence` and left out of the accuracy denominator.
- A public mirror read whose client canceled the request was logged as an error and answered `500`. It is now logged at debug and answered with nothing.
- A CLI certificate expired 7 days after it was issued unless `ztd auth enroll user` ran in its final 24 hours. Every command then failed with `remote error: tls: expired certificate`, including the `ztd auth enroll approve` needed to re-enroll expired app identities. The certificate now renews in use. An expired one is refused locally with `CLI certificate expired`, which names `ztd auth enroll user` as the recovery.

## Compatibility

This release adds no runtime storage migration, and existing roots start without `gw clean`. CLI sessions gain the optional `previous_cert_fingerprint`, `previous_cert_serial`, and `certificate_serials` fields, which only renewal writes.

Upgrade the Gateway together with the `ztd` CLI that talks to it. A Gateway earlier than this release has no renew route. Against one, Gateway client commands past the renewal time print a renewal warning with rebuild-and-restart guidance, and the certificate expires as before. The Protobuf changes are additive enum values and the optional `InferenceResult.context_window` field.

Upgrade the Inference Operators and the `ztd` that runs campaigns together. A campaign `ztd` earlier than this release cannot publish a result whose finish reason is `repetition`. An Inference Operator earlier than this release still caps output at 16,384 tokens and does not stop repetition.

The public feed requires coordinated upgrades. Upgrade the `ztd` that publishes campaign results together with the Gateway, mirrors, verifiers, and externally hosted Explorers before publishing new records. A v1.10.0 consumer accepts Explorer view schemas only through 1.14.0 and rejects the 1.15.0 records this release emits. Updated consumers keep reading earlier records. Operators do not consume the public feed. Model summaries published before this release carry no `tool_calling_exclusions` and do not qualify for the Primary or Assistant Leaderboard until `./ztd eval runs publish --all` republishes them.

New traces are `agent-trace.v12`, and campaign import and verification accept only the version the executor seals. Campaign assignments recorded with `agent-trace.v11` fail `ztd eval runs verify` as `INVALID_EVIDENCE`. `ztd public verify-agent-trace` still verifies published v3 through v12 traces.

Campaigns frozen on `default-suite@1.33.0` keep their fixtures and stored grades. Create new campaigns from `default-suite@1.34.0`, and run `ztd eval suites update` on a registered `consensus-evidence` suite. Custom-suite results stored before this release recompute their grades on verification. Those whose `LABEL_MISMATCH` detail or empty-answer trajectory now differs fail verification.

A tool result large enough to push a request past the 256 KiB message bound still ends the turn as `request_too_large`. Results are not truncated before they reach the model.
