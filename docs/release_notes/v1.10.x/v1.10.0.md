## [1.10.0] - 2026-11-04 - Public Evidence Serving

## Overview

The public feed publishes to an S3-compatible bucket, so public reads no longer reach the publishing host, and the Explorer polls files instead of holding a stream. When a bucket is configured, the Gateway's colocated publisher copies the public layout to the bucket as it changes, signs the pointer that names the current objects, and writes that pointer last. The Explorer site is a static Worker deployment.

This release stops the Evaluation Explorer from downloading every assignment result when a page loads. `/bootstrap` no longer carries assignment results. Each settled run's results are one content-addressed run bundle that the Explorer fetches when a view needs them, and a model's security score comes from a published `security_pass_rate` instead of a scan of assignments. It also corrects what the Leaderboard and the feed show for verification: a failing report now supersedes an earlier pass, and `ztd public status` reports feed drift. The platform version is v1.10.0; the Explorer's view schema advances to 1.14.0. See Compatibility for the public-feed upgrade requirement and the republish step.

## Added

- Run bundles: one gzip JSONL proof catalog artifact per settled run, `<run-id>.assignments.jsonl.gz`, holding the accepted assignment result records byte for byte with their sequence and record hash. It inherits content addressing, signed segments, withdrawal, and `ztd public verify-proof`. `evaluation_summary.assignment_bundle_sha256` names it, and the Gateway route `POST /api/v1/public-feed/proofs/run-bundle` builds it for the publishing `ztd`. An unchanged run appends nothing. A run whose records change, such as after a verification report, gets a new bundle and only the previous bundle is withdrawn, leaving the run's traces and audit databases active.
- `task_index` in `/bootstrap`: each task's 10 newest results, holding only what the Tasks view renders.
- `security_pass_rate` on model summaries: the share of judged security-policy assignments a variant and role passed, with the judged count as its denominator.
- `feed_drift` in `ztd public status`, listing each run whose stored verification report disagrees with the `verifier_state` the public read model carries. `feed_drift_checked` and `feed_drift_error` report a comparison that could not run.
- Bucket publisher: `PublicBucketPublisher` copies the colocated mirror's public layout to an S3-compatible bucket. Proof artifacts are uploaded first, then segments, catalog, history pages, read model, and the pointer. A failed step leaves the previous pointer in place, and the publisher retries it on each tick. Deletes and cache purges are journaled in `public-feed/bucket-journal.jsonl` and retried until they succeed.
- Signed pointer: `pointer.json` names the current read model, proof catalog, proof root, and proof segment head. It is signed with the feed key and written last in each sync.
- Public layout: digest-addressed objects under `read-model/`, `proofs/`, `proof-meta/`, and `proof-catalog/`, paged `proof-segments/` and `history/` chunks of 1,000, `proof-head.json`, and `live/status.json` and `live/runs/` for executing runs. The mirror's public listener serves the same objects without bucket credentials or a private key.
- `ztd public config set` bucket flags: `--bucket-name`, `--bucket-endpoint`, `--bucket-public-origin`, `--bucket-zone-id`, `--bucket-credentials-file`, and `--bucket-remove`. The credentials file holds `access_key_id`, `secret_access_key`, and `purge_token`, and the credentials are sealed under `public-feed/bucket-credentials`.
- `ztd public status` bucket report: a `Bucket:` line with the pointer revision, the sequence the pointer names, how many sequences the bucket is behind the mirror, and the pending deletes and purges.
- `ztd public verify-proof --pointer`: binds a downloaded signed `pointer.json` to the verified segment chain. The pointer must verify and name the chain's source, head segment index, and head root.
- Explorer static site config: `evaluation-explorer/wrangler.jsonc` deploys the built `dist/` to the `next.opendevops.ai` custom domain. `.github/workflows/deploy-explorer.yml` runs `wrangler deploy` for it.

## Changed

- `/bootstrap` omits assignment result projections. The mirror's stored current records are unchanged, so an existing root starts without `gw clean`, and run bundles are built from them.
- The Explorer keeps no browser copy of `/bootstrap`. Startup deletes the earlier IndexedDB database and `localStorage` key, so a returning visitor does not keep the old snapshot.
- Run Details, Assignment Details, and Model Details load the run's bundle on demand, verify its SHA-256 and each record hash, and share one fetch per run. Models, the Runs list, the Leaderboard, and Tasks read summaries and `task_index` and request no bundle.
- The Leaderboard scores security from `security_pass_rate`, pooled by its denominator, and no longer falls back to `security_resistance` or scans assignments. "Runs covered" counts the evaluations of the ranked models' datasets without reading assignment results.
- `ztd eval runs verify --publish` publishes the report whatever its outcome, through the path `runs publish` already uses, and refuses `--require-provenance` or `--require-observation` when the flag is stricter than the run's frozen policy.
- A rollout stops a run at its first `model_not_found` result and leaves the remaining assignments queued, because a provider without the model cannot attest a provenance window for it.
- The Explorer view schema is 1.14.0. Updated consumers continue to accept historical records from 1.0.0 through 1.13.0, subject to the existing rejection of the removed `assignment_audit_vault_key` evidence kind.
- The Explorer and `ztd-adapter` read `pointer.json` and the digest-addressed read model, live status, and proof paths. Pointer polling runs about once a minute while the tab is visible, and live status polling runs about every 10 seconds while the pointer reports an active run. The Explorer no longer holds an SSE connection to the public feed.
- `/stream` is removed from the mirror and from the `ztd-adapter` public client. The Explorer reads the layout. The platform SSE bridge (`/api/v1/sse/stream`) is unchanged.
- The `ztd-adapter` public client interface changes. `PublicClient` reads the pointer, the read model the pointer names, live status, the proof catalog, and proof head. The `bootstrap`, `snapshot`, `snapshotAt`, and `history` methods are removed, and `proofCatalogEntry` takes an artifact ID without a source ID.
- The offline verifier documentation describes `ztd public verify-proof --pointer`.
- The Evaluation Explorer has a new visual system for dark and light themes: IBM Plex type served from the site itself, hairline structure with square corners, status color only where it carries status, and a one-color logo. In audited default states, text reaches 4.5:1 contrast and form-control boundaries reach 3:1 on every surface.
- The Explorer footer shows the feed's sequence and last accepted time, and stays one row below desktop widths.
- On a phone the Explorer opens on the content with the navigation drawer closed, and following a drawer link closes the drawer.
- Live activity rows are compact: a tribunal seat shows its name and any vote, and its office is in the seat's title and in the open vote.
- The Live column is named Status and shows Running while an assignment is active. Loading its terminal result from a run bundle, or reading its recent task-index outcome, updates every role's status even when the bounded feed has no terminal event, fixing lingering Invoked indicators. Rows of ended runs with no published assignment outcome show Status unavailable.

## Fixed

- The Leaderboard opens on Formations when the selected release has formation rows and no model rows, so a release whose runs are all formation runs no longer opens on empty Overall, Primary, Assistant, and Lite boards. An explicit selection wins and survives a reload.
- A failing verification report published after a pass downgrades the run, its model summaries, and every assignment row. A later pass restores them. Before, assignment rows stayed `verified`, and fixed idempotency keys suppressed the later publication.
- The Explorer no longer builds and scans a full copy of the assignment map on page load.
- Opening an Explorer model URL directly no longer crashes the page.
- Explorer section links land at the top of the scrolling pane. Docs sections and assignment evidence links stopped up to 100 pixels low.
- Long Explorer IDs and digests wrap on narrow screens instead of widening the page.

## Compatibility

This release keeps the platform CLI and Protobuf contracts and adds no runtime storage migration: the new storage is additive, and existing roots start without `gw clean`.

The public feed requires coordinated upgrades: upgrade the `ztd` that publishes campaign results together with the Gateway, mirrors, verifiers, and externally hosted Explorers before publishing new records. A v1.9.1 consumer accepts Explorer view schemas only through 1.13.0 and rejects the 1.14.0 records emitted by v1.10.0, and the v1.10.0 Explorer requires the `task_index` that only a v1.10.0 Gateway serves. A Gateway that predates the run-bundle route rejects the publishing `ztd`'s bundle request, so the run's summary is not exported. Operators do not consume the public feed and need not upgrade together with its consumers.

Run `./ztd eval runs publish --all` after upgrading. A run published before this release has no bundle, so the Explorer shows no assignment details for it, and its model summaries carry no `security_pass_rate`, so its Primary and Assistant models do not qualify for the Leaderboard. Republishing uses the records the mirror already holds. `--all` does not cover archived runs; publish those by run ID.

A settled run's bundle is immutable and named by its digest. An executing run's assignment details come from a mutable live object, `live/runs/<run-id>.jsonl.gz`, which can lag by up to a minute plus its 60-second cache.

Bucket publication is optional. A configuration with no bucket fields does not publish to a bucket, and the mirror serves the layout without one. Enabling the bucket requires `ztd public config set --bucket-*` on the Gateway and a restart. A Gateway whose mirror origin is not local refuses a bucket configuration. Missing bucket credentials are logged, and the mirror keeps serving.
