## [1.0.6] - 2026-10-13 - Cross-Platform Host Support and Tooling

### Overview

v1.0.6 is a cross-platform host support and tooling reliability release on top of v1.0.5. It delivers robust process management on Windows using Job Objects, interactive OS keystore authorization tolerance on macOS (Darwin), host RAM observation on Darwin, dual-stack network port conflict detection, scenario workspace drive-letter path normalization for Windows, protocol extensions for inference keep-alive and observer pseudonyms, and active preflight R2 credentials probe verification in release tooling.

### Highlights

* **Windows Host Support** — Native Windows Job Objects manage operator and child processes, ensuring reliable process cleanup on exit and robust process isolation in release smoke tests.
* **macOS (Darwin) Reliability** — Tolerates OS keychain approval prompts with configurable delay windows; implements Darwin host RAM metrics collection and dual-stack port conflict detection.
* **Evaluation Hardening** — Resolves Windows drive-letter scenario workspace paths and introduces Data Operator working directory preflight validation.
* **Protocol Extensions** — Extends `OperatorRegistration` with `inference_keep_alive`, `provenance_operator_id`, and `provider_boundary_observer_id`.
* **Release Tooling Hardening** — Probes Cloudflare R2 credentials with an active write/read/delete preflight check before builds and rehearses publication.

### Added

* **Windows Job Object Operator process management** — Implemented Windows Job Objects in `internal/cli/cmd/operator/operator_stop_local_windows.go` and `internal/services/system/system_utils_windows.go` to reliably terminate local operator processes and all spawned child processes on Windows.
* **Release smoke runner isolation on Windows** — Added `internal/cli/cmd/test/release_smoke_process_windows.go` to handle process group and Job Object cleanup during headless release smoke runs on Windows.
* **Windows MCP system info tooling** — Added `internal/services/mcp/sys_info_windows.go` implementing Windows-specific host telemetry, memory metrics, and OS version interrogation via system utilities, covered by unit tests in `internal/services/mcp/sys_info_windows_test.go`.
* **macOS OS key store approval tolerance** — In `internal/constants/platform.go`, added `KeyStoreApprovalNoticeDelay` (2s) and `KeyStoreApprovalTimeout` (5m). Background `ztd gw start` detects `[Keystore] Waiting for approval to read the master key from the OS key store` when macOS Keychain displays an interactive authorization prompt, continuing to wait rather than failing prematurely.
* **macOS local operator stop** — Added `internal/cli/cmd/operator/operator_stop_local_darwin.go` providing graceful signal dispatch and process group cleanup on macOS.
* **Darwin host RAM observer** — Added `internal/services/inference/provider_observer/host_ram_collector_darwin.go` using Mach/sysctl telemetry to measure host RAM accurately on macOS.
* **Operator registration protocol extensions** — Added fields 17, 18, and 19 to `OperatorRegistration` in `protocol/proto/ztd/operator/v1/operator.proto`: `inference_keep_alive` (`--inference-keep-alive`), `provenance_operator_id` (`--provenance-operator-id`), and `provider_boundary_observer_id` (`--provider-boundary-observer-id`), with generated Go and TypeScript bindings in sync.
* **R2 credentials preflight probe** — Added `check` subcommand to `scripts/release-r2.sh` that executes an active probe (write, read back, delete) under `_preflight/` in the `ztd-releases` bucket on every run, including rehearsals, before building.
* **Evaluator scenario workspace validation** — Added `ValidateOperatorWorkingDirectory` and integrated it into `runs_execute.go` to validate Data Operator working directory bindings before dispatching benchmark models.

### Changed

* **Scenario workspace paths on Windows** — Updated `internal/services/evaluation/scenario_workspace.go` to handle Windows drive-letter paths (`D:/x/y`) alongside POSIX paths without path delimiter corruptions.
* **Network & SSH port selection** — Enhanced TCP port conflict probe to check both IPv4 and IPv6 listener bindings, and maintained SSH ProxyCommand process keep-alive across handshakes.
* **Release set manifest ordering** — `scripts/release-r2.sh upload` uploads `ztd-binaries.json` last, ensuring that a version appears on `/releases/` only after the full release artifact set is present in R2.
* **Makefile test package exclusion** — Updated `TEST_EXCLUDE_PKGS` in `Makefile` to include `ztd/test`, preventing recursive test execution loops.
* **Line ending governance** — `.gitattributes` now enforces `* text=auto eol=lf` across the repository while pinning `*.ps1` to CRLF.
* **Releases interface & onboarding** — Added website release rendering in `website/src/releases.js`, `website/src/release-notes.js`, `website/src/layout.js`, and `website/static/start.sh` with Vitest coverage in `website/test/releases.test.js` and `website/test/start.test.js`.

### Removed

* **Obsolete journal icon asset** — Removed `website/static/journal-icon.svg`.

### Fixed

* **Operator process termination on Windows** — Resolved dangling background operator child processes by binding operator processes to Windows Job Objects with `KillOnJobClose`.
* **Darwin TCP port listener conflicts** — Fixed dual-stack IPv4/IPv6 port probe conflicts that previously caused flaky listener bindings on macOS.
* **Darwin SSH ProxyCommand lifecycle** — Fixed unexpected termination of ProxyCommand processes during SSH handshakes.
* **Evaluation campaign execution on Windows** — Fixed path normalization errors during scenario workspace initialization when drive letters were present.
* **Cobra CLI flag parsing** — Fixed sub-command flag parsing edge cases in Cobra command dispatch.
* **Evaluation resident provider model cleanup** — Fixed resident provider cleanup upon scenario completion.
