## [1.0.5] - 2026-10-13 - Onboarding and Host Configuration

### Overview

v1.0.5 is an onboarding and host-configuration release on top of v1.0.4. Every `./ztd` command now loads an owner-only repo-root `.env` holding user secrets and user-specific endpoints, `make up-public` and `make gw-public` start a Gateway reachable from other hosts, `ztd gw start` refuses to report success against a running Gateway whose startup configuration differs from the request, and an outbound Operator refuses to open a Gateway's runtime tree. The governance pipeline, protocol contracts, and storage layout are unchanged from v1.0.4.

### Added

* **Repo-root `.env`** — Every `./ztd` command loads `.env` from the working directory at startup through `config.LoadEnvFile` (`internal/cli/config/env_file.go`). Only the `secret` and `user_endpoint` keys in `protocol/constants/env_vars.json` are accepted; an unknown key or a line that is not `KEY=VALUE` stops the command (`ErrEnvFileUnknownKey`, `ErrEnvFileMalformed`). A variable already exported in the shell wins over the file, and an explicit flag wins over both. On Linux and macOS the file is opened without following symlinks or blocking on a FIFO, and must be a regular file owned by the user or root with mode `0600` or `0400` (`ErrEnvFileInvalid`). A missing `.env` loads nothing. See [Configure `.env`](../../guides/getting_started.md#configure-env).
* **Setup creates `.env`** — `scripts/linux-setup.sh`, `scripts/macos-setup.sh`, and `scripts/windows-setup.ps1` copy `.env.example` to `.env` after building `./ztd` (mode `0600` on Linux and macOS) and keep an existing `.env`. Every template entry is commented, so the default flow loads no keys.
* **`ZTD_OLLAMA_ENDPOINT`** — A new `user_endpoint` registry key that supplies `--inference-ollama-endpoint` for `ztd gw start`, `ztd operator start`, and `ztd operator model` commands when the flag is blank. Set it in `.env` when the approved Ollama provider is not on the Gateway or Operator host.
* **`make up-public` and `make gw-public`** — Run `make up` and `make gw` with `--listen-host 0.0.0.0` so Operators on other hosts can enroll. `make up` and `make gw` stay loopback-only.

### Changed

* **`ztd gw start` against a running Gateway** — The running-process check now precedes network identity detection. Every startup flag the caller set explicitly (`--capabilities`, `--posture`, `--listen-host`, `--http-port`, `--https-port`, `--model-storage-root`, `--inference-ollama-endpoint`, `--public-base-url`, `--cors-origin`, and the passkey relying-party flags) is compared with the running launch profile. A match reuses the running Gateway; a difference prints the current and requested values and fails with `ErrGatewayAlreadyRunning`. A `ZTD_OLLAMA_ENDPOINT` value (exported or from `.env`) counts as requesting `--inference-ollama-endpoint`, so editing it and rerunning `make gw` reports the difference instead of silently keeping the old endpoint. A bare `gw start` with no such value still reuses whatever Gateway is running. Previously the command reported "already running" and exited 0 while the old configuration stayed active.
* **Gateway startup output** — `gw start`, `gw restart`, and `gw connect` print the detected network identity only when the listeners bind a routable interface. The post-start guidance is a single Console origin and a short command list (`login` / `login web` ordered by posture, a same-host or remote `operator start` with its own `--working-dir`, `auth enroll pending`, `gw status`). `gw restart` prints the same guidance as `gw start`.
* **Copy-paste-safe command output** — Every command the CLI prints for the user to run sits alone on its own line, flush-left, with no quotes, prose, or indentation around it. This covers the loopback notice (`gw stop`, then `gw start --listen-host 0.0.0.0`), the `gw start` next steps (a purpose line, then the bare command), tunnel and swagger hints, `--help` text and error messages that name a command (for example `Enroll first with:` followed by `./ztd auth enroll user`), the eval and vault hints, and the TUI status lines, where the command is unquoted at the end of the line. Stray duplicate and misspelled output, such as `ztd.operator stream --help`, is fixed.
* **Enrollment approval hint** — Application and Operator enrollment requests print `Approve on the Gateway host with:` followed by `ztd auth enroll approve <id>` on its own line.
* **`make status`** — `make status` runs `ztd gw status` only, which already includes the Operator inventory and pending enrollments.
* **`.env.example`** — Lists every `secret` and `user_endpoint` registry key, including `CLOUDFLARE_API_TOKEN`; the `make constants-check` exemption for that key is removed.
* **TLS bundle logging** — Per-certificate `[TLS-DEBUG]` bundle lines log at debug level instead of info.
* **Website reduced motion** — With `prefers-reduced-motion: reduce`, the homepage (`website/src/index.html`) drops shake, jitter, and slide offsets and slows the background grid and ticker instead of disabling every animation and transition. Reveal and trace rows still fade in, and the grid stops drawing while the page is hidden.
* **Deterministic OpenAPI** — `.swaggo` overrides `webauthncose.COSEAlgorithmIdentifier` to an integer so `make swagger-generate` output no longer depends on map order, and swag errors are reported (`--quiet`) instead of discarded.

### Removed

* **`public_feed_outbox` collection constant** — `CollectionPublicFeedOutbox` had no readers or writers and is removed from `internal/constants/collections.go`.
* **`make up` follow-up hints** — The status and sign-in lines `make up` printed after `gw start` are removed; `gw start` prints the guidance itself.

### Fixed

* **Operator in a Gateway runtime tree** — `ztd operator start` refuses a runtime tree that holds the Gateway root CA (`GatewayRuntimeMarker`, `pki/root/root_ca.crt`) and exits with a configuration error naming `--working-dir` (`ErrOperatorGatewayRuntime`, INV-OP-STOR-03). An Operator launched from the Gateway directory without `--working-dir` previously opened the Gateway's audit database and vault. `ztd operator reset-identity` uses the same marker.
* **Local receipt reads in tests** — `storage.ReadLocalActionReceipt` is the single reader of a runtime's sealed local receipt. Release smoke and the deploy lifecycle E2E use it; the E2E previously parsed the encrypted `receipt_json` as protojson. The lifecycle cancellation case omits `--approve` so only the worker dials the stalled HTTPS port.
* **Test isolation from `.env`** — `ztd test` runners (unit, integration, E2E, coverage, release smoke, scale) start their child processes without the `secret` and `user_endpoint` keys (`config.WithoutUserEnv`). Because every `./ztd` command loads `.env`, test processes previously inherited the developer's `CLOUDFLARE_API_TOKEN` and `ZTD_OLLAMA_ENDPOINT`, and the release smoke Gateway and worker inherited the developer's Ollama endpoint.
* **`auth enroll user` help** — Named a nonexistent `auth enroll operator` command; it now points to `operator start` and `auth enroll approve`.
* **`operator start --endpoint host:port`** — The global `--endpoint` help accepts `host:port`, but `operator start` appended its own port, so the pub/sub URL became `wss://[host:port]:8443` and the Operator could not connect. The endpoint port now sets the Gateway HTTP discovery port; a port that differs from an explicit `--gateway-http-port`, a URL scheme, or an invalid port fails at startup with `ErrGatewayEndpointInvalid`. Workers deployed by `operator deploy` with a `host:port` endpoint had the same failure.
* **E2E environment keys** — `ztd test scale` and the E2E suite exchanged twelve `ZTD_E2E_*` keys (`ZTD_E2E_RUNTIME_ROOT`, `ZTD_E2E_GATEWAY_HTTP_PORT`, `ZTD_E2E_GATEWAY_HTTPS_PORT`, `ZTD_E2E_MASTER_KEY_FILE`, and the `ZTD_E2E_FLEET_*` keys) through local string constants outside `env_vars.json` (INV-ENV-04). They are now `test` registry keys read through `constants.EnvVar`, and `TestProductionGoEnvReads_UseRegistryKeys` also rejects local string constants and covers `test/`.
* **Collections registry** — `protocol/constants/collections.json` omitted ten `CollectionName` constants (`consensus`, `enrollment_tokens`, `cli_recovery_requests`, six `observe_*` projections, and `eval_campaign_publication_state`). They are listed, and `TestCollectionsRegistryMatchesGoConstants` fails on drift in either direction.
