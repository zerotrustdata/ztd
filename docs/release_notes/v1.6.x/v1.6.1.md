## [1.6.1] - TBD - Evaluation correctness and release reliability

Status: unreleased draft. No release date or live qualification is claimed.

## Added

- The Evaluation Explorer Live view shows the pinned judge in the judged assignment's own row, joined by assignment identity like Tribunal votes. A Judge cell lists every judgment as it starts and completes, with its verdict or failure code, and expands to the judge model, rubric, rationale, tokens, provider timings, execution time, live wall time, attempt and transaction. Both judging paths, criteria and diagnosis or memory quality, publish `judge_started` and `judge_completed` live events.

## Fixed

- The judge no longer shares the provider with the model it grades. Before each assignment, and before each tool-calling probe, the executor releases every resident model except the ones that assignment dispatches. Before the judge's first dispatch, it releases every model except the judge. Every run releases its resident models when it finishes or fails, so the strict-observation release at run start is gone. Each release is a governed typed residency read plus a batch release on the Inference Operator, outside the attempt's ledger bracket. Under `ratify` and `notary`, each release waits for an L3 approval.
- The hidden `ztd operator model residency` subcommand is removed. It read only Ollama and duplicated the governed residency command, which serves both providers. A governed residency result naming a model without a name now fails closed instead of being dropped.
- A failed tool-calling eligibility dispatch stops execution instead of being converted into a scored provider failure for every tool-bearing cell. A capability exclusion still requires the verified, signed negative probe.
- File history returns commits that change the requested encrypted snapshot, excluding unrelated commits. It looks up the path directly in each commit and its parents, honors request cancellation, and propagates unreadable-history errors. Governed history, diff and restore retain their signed receipts and offline verification.
- Grading contract v4 rejects clarification questions as a substitute for a required answer. Its parser accepts trailing `(YES/NO)` and leading “Yes or no:” markers while retaining the three-question, whole-response and closed-question checks.
- V4 Triage grading accepts every frozen allowed complexity, intent and posture label, rather than only the first item. Older grading contracts retain their historical interpretation.
- `tech-log-parse` passes a reply that names `checkout-api`, including one written as a sentence, rather than requiring the whole reply to be the bare label. A reply naming the upstream `payments` host still fails.
- Config-comparison evidence explicitly identifies old and new states of one service, matching the unchanged change-and-impact rubric.
- The scripted tool-probe integration fixture supplies the required content-judge reply and checks that it remains outside the scored model turns.
- Release scripts validate artifacts and stage upload inputs before publishing, with hermetic shell regression coverage.

## Changed

New campaigns freeze `default-suite@1.31.0`, `smoke-suite@1.30.0`, `investigations@1.27.0`, `quickstart@1.1.0`, and grader `1.19.0`. Default and smoke scenarios use `2.6.0`, except `tech-log-parse` at `2.6.1`; investigation scenarios use `2.3.0`. The checked-in consensus screening/evidence suites advance to `1.8.0` and safety to `1.6.0`. Existing campaigns and recorded evidence retain their original frozen contracts. Counts remain 41 default scenarios and 85 doctrine/ratify or 78 consensus/notary cells per model.

Every grader call now carries its judge inference's signed result and receipt, for criterion and quality judgments alike, and `ztd eval runs verify` checks the receipt, the result digest and the verdict decoded from the signed result against each judged grade. A judged result recorded without this evidence, or from a campaign that froze no judge, no longer verifies. Deferred `ztd eval runs publish` rebuilds the judge events from the persisted grader calls, so they are included in `assignment-<id>.db`. The Explorer view contract advances to schema `1.11.0`, which the Gateway's Tribunal votes also stamp. Mirrors, verifiers and externally hosted Explorers must be upgraded with the publisher: an older mirror rejects the new event kinds, and publication fails closed with `ErrEvaluationPublicationFailed` while the result stays persisted and republishable.

A 16-case manually reviewed criterion fixture under `eval/judge-calibration/` preserves exact historical prompts and both positive and negative examples for judge comparisons. It is diagnostic data, not a representative accuracy benchmark or new qualification evidence. No replacement judge is selected by these changes.
