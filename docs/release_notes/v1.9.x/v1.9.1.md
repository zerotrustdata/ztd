## [1.9.1] - 2026-11-04 - Published Formation Results and Persona Demos

## Overview

This release replaces the Evaluation Explorer's static formation catalog with results from published runs. Formations have their own leaderboard, and Models and Model Details show their published formation membership. It also adds five checked-in persona scenarios for local governed agent demo recordings. The platform version is v1.9.1; the Explorer's separate view schema advances to 1.13.0. See Compatibility for the public-feed upgrade requirement.

## Added

- Typed per-formation summaries in `evaluation_summary.formations`, derived from each frozen stack's exact assignment population. Each summary publishes the stack identity and digest, Primary, Assistant, and Lite bindings, outcomes, judged accuracy, security-task pass rate, inference performance, execution time, and known total parameters and installed artifact bytes. Missing observations remain unavailable, and member variants shared across roles count once toward size totals.
- A Formations leaderboard that scores complete stacks with the existing score formula. Completed, verified runs qualify only with full formation execution coverage and the required parameter, latency, and token observations. Suites and frozen stack versions rank separately; repeated runs pool judged counts and weight performance statistics by judged assignment count. The artifact budget applies to the whole formation.
- Five checked-in Zero Trust Paper Company demo scenarios for finance, operations, procurement, customer support, and compliance. `make vhs SCENARIO=priya-finance` records one; `make vhs-scenarios` records all five, with an `ONLY` selector for a subset. The batch writes an index linking videos, prompts, signed tool calls, recording attempts, and audit chain results. These recordings run locally and require the existing recording tools and local models.

## Changed

- The Evaluations Formations tab and Run Details render published frozen formation summaries. Models and Model Details derive membership from the same feed, including project-specific formations, rather than a manually maintained catalog or inferred VRAM estimates.
- Formation slot model specifications come from the campaign's frozen model registry, allowing the published summaries to carry retained model metadata.
- The Explorer view schema is 1.13.0. Updated consumers continue to accept historical records from 1.0.0 through 1.12.0, subject to the existing rejection of the removed `assignment_audit_vault_key` evidence kind.
- The website adds the Build in Public post “Shirtless in a field with a reference monitor.”

## Fixed

- Whole-formation outcomes no longer contribute individual-model leaderboard scores.
- The Leaderboard opens on the newest release series with a rankable model or formation, so formation-only results can select the default release. An explicit `?release=` still takes precedence.
- Model run lookup scopes assignment references by dataset and run ID and also reads published role bindings and formation summaries, so membership does not depend on the browser retaining every assignment.
- `ztd eval runs repair` records a terminal assignment with no persisted result, such as one `ztd eval runs cancel` stopped, as a `recovered_without_result` failure that verifies. Before, repair recorded `internal_error` with the assignment's lifecycle, which `ztd eval runs verify` rejected for every lifecycle except `FAILED`. Repair also replaces the results an earlier repair recorded in that form.
- `ztd eval runs verify` no longer fails a run because a tool-bearing assignment that failed without a trace has no tool-calling probe. A probe with no signed verdict records no probe and fails only its assignment, so these runs could never verify.
- `ztd eval runs verify` accepts `provider_stream_error` as a provider failure reason. It was missing from the verifier's list of attempt classes.
- A final harness check that governance denies no longer marks a valid trace `INVALID_EVIDENCE`. Its signed rejection now verifies, and the affected grades are `UNAVAILABLE`, because the outcome was not measured.
- A formation's Interrogator call on the Lite slot no longer fails evidence verification as a role mismatch.
- `INVALID_EVIDENCE` results publish a fixed reason that names the evidence stage that failed. Assignment details and `ztd eval runs assignments --failed` show it. The raw detail stays local.
- `ztd eval runs repair --regrade` now includes formation assignments and replaces an `INVALID_EVIDENCE` result whose reason differs.
- The Explorer Live view settles every role row of a formation assignment when the assignment ends. Before, Lite and Assistant rows stayed `Invoked` indefinitely, so finished assignments looked like parallel running ones.

## Compatibility

This release keeps the platform CLI and Protobuf contracts and adds no runtime storage migration. Operators do not consume the public feed and need not upgrade together with its consumers.

The public feed requires coordinated upgrades: upgrade the `ztd` that publishes campaign results together with the Gateway, mirrors, verifiers, and externally hosted Explorers before publishing new records. A v1.9.0 consumer accepts Explorer view schemas only through 1.12.0 and rejects the 1.13.0 records emitted by v1.9.1. Updated consumers retain support for v1.9.0 records. The public-feed schema change therefore requires coordination despite this release's patch version.

A result an earlier `ztd eval runs repair` recorded as `internal_error` with a lifecycle other than `FAILED` fails verification until `ztd eval runs repair <run>` replaces it.

A stored `INVALID_EVIDENCE` result without a public reason, or one recorded by the checks this release fixes, fails verification until `ztd eval runs repair <run> --regrade` replaces it. Then run `ztd eval runs verify <run>` and `ztd eval runs publish <run> --force`.

Historical runs remain readable but need republishing to expose formation summaries. After upgrading and restarting the Gateway, run `./ztd eval runs publish <run-id> --force` for each affected run. Republishing projects retained frozen evidence without rerunning inference or rewriting signed history. See the [Explorer runbook](../../../evaluation-explorer/RUNBOOK.md#expected-browser-states) and [formation contract](../../../evaluation-explorer/src/contract/CONTRACT.md#frozen-formation-summaries).
