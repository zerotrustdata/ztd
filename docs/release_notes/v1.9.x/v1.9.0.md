## [1.9.0] - 2026-11-04 - Deterministic Grades in the Live View

## Overview

This minor release shows an assignment's deterministic grades in the Evaluation Explorer Live view, in a Deterministic column between Consensus and Judge, and removes the Input column so that the row's columns fit. It also adds `make vhs` for recording governed agent demos, and stops a file mutation's diff from holding the ledger write lock. The `ztd` that runs a campaign, the Gateway, mirrors, verifiers, and externally hosted Explorers must upgrade together; Operators need not upgrade with them. See Compatibility.

## Added

- A Deterministic column in the Live view, between Consensus and Judge, with one circle per criterion in grading order. Each circle shows its verdict by color and symbol and opens to the criterion, result, and grader detail, one at a time in a row. The column appears when a row on the page has grades or is waiting for them.
- The `deterministic_grading_completed` live event and its typed `PublicLiveDeterministicGrade` block: criterion, status, and grader detail, the same content the assignment's public grade summary publishes. An assignment publishes one event, holding every grade, as soon as its sealed trace is graded. That is after the content judgments, which the `scenario-content` grade includes, and before the quality judge, so a running row can show Judge verdicts before its circles, and its Deterministic cell reads Pending until they arrive. A terminal row without grades stays empty.
- Deferred publication rebuilds the event from the persisted result ahead of the assignment's terminal events, so it reaches `assignment-<id>.db`. The publication key names the graded content: identical grades publish once, and a persisted result that holds different grades publishes a later event that replaces them in the row.
- `make vhs` records a governed agent run against the Zero Trust Paper Company, then its receipts, audit chain, and TUI, through `scripts/demo-record.sh`. It does not download models.

## Changed

- The Explorer view schema is `1.12.0`. Every live event is stamped with it, and records from `1.0.0` through `1.11.0` still decode.
- The Live view no longer has an Input (tok) column. Output (tok) stays, and the assignment page still reports input tokens.
- Consensus and Judge are narrower in the Live view, and beside an open navigation drawer the fixed columns tighten so that every column fits without horizontal scrolling.
- An assignment whose only published live record is its deterministic grades, such as one stopped by a failed tool-calling probe, now has an audit database and its evidence binding.

## Fixed

- The Evaluation Explorer Leaderboard opens on the newest release series with a model it can rank, rather than on the build's series. A platform upgrade, or a run still in progress on a newer series, no longer opens the page empty. An explicit `?release=` still wins, and the build's series is the default only when no model in the feed can be ranked.
- A file mutation's diff no longer holds the ledger write lock. The lock is shared by every session of a runtime and the diff's cost can grow with the square of the file's size on a large rewrite, so one such rewrite could stall ledger writes in every session.
- The diff stat recorded for a new file counts its lines correctly. A file ending in a newline reported one line too many, and an empty file reported one line. Rows already recorded keep their text.

## Compatibility

Verdicts, scores, and persisted evaluation results do not change, and existing runtime roots keep starting: this release adds no storage. Operators do not read the public feed, so they can stay on 1.8.0; a 1.8.0 Operator keeps holding its ledger write lock during a diff until it upgrades.

Upgrade the `ztd` that runs a campaign together with the Gateway, mirrors, verifiers, and externally hosted Explorers. A 1.8.0 Gateway or mirror rejects a `1.12.0` live event as an unsupported schema version, so a 1.9.0 campaign cannot publish through it, and a 1.8.0 Explorer does not decode these events. A 1.8.0 verifier rejects an `assignment-<id>.db` that contains a `deterministic_grading_completed` event. In the other direction, a 1.9.0 Gateway, mirror, verifier, or Explorer accepts everything 1.8.0 publishes.
