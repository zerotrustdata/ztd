## [1.4.1] - 2026-10-25 - Operator Ownership and Evaluation Reliability

## Overview

v1.4.1 fixes inference and Tribunal evaluation paths, clarifies Operator capability ownership, improves public mirror performance, and streamlines Evaluation Explorer startup. The embedded Operator now defaults to `data` only; pass `ztd gw start --capabilities data,inference` to keep embedded inference.

## Added

- Governance deliberation results retain Tribunal vote inference evidence, and conformance runs can verify Tribunal deliberations through `POST /api/v1/governance/deliberations`, including supporting inference and observation runtimes.
- Evaluation run and assignment correlation fields associate Tribunal vote activity with its campaign assignment.
- Operator capability ownership checks reject duplicate actuator keys and prevent singleton `inference`, `provenance`, or `observer` capabilities from being claimed by multiple Operators. Outbound Operator startup holds `operator.lock` to prevent multiple processes from sharing a runtime directory.

## Changed

- Inference, provenance, and observer capabilities require explicit selection; `ztd gw start --capabilities data,inference` opts the embedded Operator into inference.
- Inference selection prefers an eligible embedded Operator and preserves explicit errors for targeted sessions that lack the inference capability.
- Public mirror indexes cover additional query columns, and ingest batches writes to reduce query and update overhead. Changed indexes use new names so upgraded `mirror.db` files build the covering indexes.
- Evaluation Explorer displays a spinner while connecting, caches a validated bootstrap for faster startup, and avoids downloading the full bootstrap when a cached feed can catch up through the stream.

## Fixed

- Ollama requests no longer fail when a model value uses the supported model representation.
- Tribunal vote events retain their campaign run and assignment identity, and unassigned or unrelated governance votes no longer appear on campaign assignment rows.
- Tribunal voting assignment fixes preserve inference evidence across revised or failed admission reviews.
- Website version display updates with the release preparation, and the website journal includes the event receipt illustration.

## Qualification evidence

The Linux amd64 candidate builds successfully and reports `v1.4.1`. The Explorer and Console production bundles build with TypeScript checks, and the Console embed matches its source build. Runtime release-smoke was not run during this preparation.

## Compatibility

The embedded Operator capability default changes from `data,inference` to `data`. Existing workflows that require embedded inference must opt in with `ztd gw start --capabilities data,inference`.

The protocol adds optional `evaluation_run_id` and `evaluation_assignment_id` fields to `GovernanceEnvelope`, plus typed deliberation and conformance evidence fields. These are additive protobuf schema changes. Mixed-version Gateway/Operator operation was not exercised during this documentation and build preparation. The correlation fields provide display context and do not grant authorization.
