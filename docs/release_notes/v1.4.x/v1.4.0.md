## [1.4.0] - 2026-10-24 - Event Receipt Contracts and Public Evaluation

Release preparation draft. Planned tag date: 2026-10-24 UTC.

## Overview

v1.4.0 names the signed evidence of a governed request `EventReceipt` throughout the protocol, native MCP queries, evaluation retrieval, and compliance tooling. It strengthens Tribunal authoring validation, adds dedicated Leaderboard and Sponsors pages to the Evaluation Explorer, introduces the Zero Trust Paper Company business sandbox, and expands the maintained test and onboarding gates.

The change inventory covers the 15 commits from tag `v1.3.0` through `e2a026897c18239daa6b975b104f1697b978a0be`, plus the release preparation changes in this working tree. Breaking tool, generated API, retrieval-query, and evidence identifiers require the minor version bump under `INV-REL-VER-10`.

## Added

- The Evaluation Explorer has a dedicated `/leaderboard` page with role rankings and an artifact-size filter, separate from the Models capability catalog. Its Sponsors page provides project support and contact routes.
- The Zero Trust Paper Company demo supplies Python/SQLite business systems, seeded identities, documents, and repeatable cross-system scenarios. Role permissions cover customer onboarding, sales, finance, purchasing, inventory, dispatch, HR, support, and document retrieval. Demo API authorization and the ztd execution boundary are distinct; see the [demo guide](../../../demos/zero-trust-paper-company/README.md).
- `make generate` sequences maintained artifact generators, and `make demos-test` runs the business sandbox checks. The expanded `make test` gate sequences quality, platform, component, script, process, fleet, and Docker onboarding checks, including a default 100-Operator fleet smoke. Live provider runs and tests against an existing Gateway remain explicit targets.

## Changed

- The canonical protobuf message is `ztd.operator.v1.EventReceipt`, replacing `ActionReceipt`. Searchable event records embed it under `event_receipt`. Runtime APIs use `LocalFirstEventsStore`, `LocalFirstEventsStoreConfig`, `NewLocalFirstEventsStore`, and `GetLocalFirstEventsStore`.
- Native MCP receipt queries are `event_receipt_list` and `event_receipt_get`. Investigation retrieval uses `exclude_event_receipt_reads`. Compliance artifact identifiers, schema references, and receipt reference prefixes use event receipt terminology.
- API path registry keys are `audit_event_receipts` and `audit_event_receipts_export`. The HTTP paths remain `/api/v1/audit/event-receipts` and `/api/v1/audit/event-receipts/export`.
- Built-in suites advance to `default-suite@1.15.0`, `smoke-suite@1.15.0`, and `investigations@1.15.0` for receipt-query contract changes. Frozen campaign catalogs and recorded results keep their original scope.
- Tribunal authoring instructions distinguish direct argv from shell expansion and preserve utility-specific literal syntax. Nemesis's generation prompt now requests an intentionally incorrect negative-control proposal; existing consensus logic excludes Nemesis and matching proposals from the vote. Its L2 voting stance now checks destructive effects, exfiltration, persistence, privilege escalation, and evasion.
- The inference output ceiling is 16,384 tokens, reduced from 256,000. An unset limit uses the new ceiling; requests exceeding it fail validation.
- Website updates link to live evaluation and sponsorship routes and add the event receipt journal entry.

## Removed

- The protobuf source name `ActionReceipt`, native MCP names `audit_receipt_list` and `audit_receipt_get`, and retrieval key `exclude_audit_reads` have no compatibility aliases.
- Role rankings move out of the Models page into the dedicated Leaderboard page.
- Claude Code configuration drops obsolete REPL and MultiEdit tool identifiers from its deny list.

## Fixed

- Tribunal generation, Marshal, and Auditor enforce the response schema supplied to the provider. Invalid responses receive corrective feedback within the existing retry limits rather than accepting missing fields, null strings, case-insensitive keys, or invalid verdict shapes.
- Public spectator startup binds listeners before resolving URLs, so ephemeral port assignments propagate to feed origins, Explorer configuration, and Gateway state. Listen validation permits separate kernel-assigned ephemeral ports.
- Linux setup maps logical dependencies to the correct apt, dnf, pacman, and zypper package names. Docker onboarding snapshots record a source revision for release evidence.
- Historical `v1.3.0` notes are restored to their tagged contents; post-tag changes are attributed to this release.
- The README states the Linux and Python prerequisites for the aggregate test gate.

## Compatibility

Upgrade clients that consume generated protobuf APIs, MCP receipt queries, retrieval queries, or compliance artifacts. Gateways and Operators participating in the renamed query contracts should use the same release; no legacy tool aliases are provided.

- Protobuf receipt field numbers and JSON payload fields are unchanged, as are canonical receipt signing bytes and persistence attestations. Generated type names and descriptors change. Searchable record wrappers use `event_receipt`; dispatch responses continue to use `receipt`.
- The runtime SQLite schema already stores receipt stages on `events` with `event_receipt_*` columns in `v1.3.0`; this release's store rename introduces no new database migration. The receipt chain event type and `receipts:` pubsub channel prefix are unchanged. An Operator's local store remains authoritative; Gateway receipt mirrors remain best-effort projections.
- Older traces containing `exclude_audit_reads` and bundles containing action receipt identifiers require the verifier from the revision that produced them. Use the original verifier for historical evidence; this release supplies no conversion or compatibility alias. New campaigns freeze the current tool catalog.
- Existing inference callers that request more than 16,384 output tokens must lower their requested limit.
