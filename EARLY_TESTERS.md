# Feedback and bug reports

This document describes how to report feedback and bugs for ztd.

## Channels

- **GitHub Issues** — bug reports and reproducible defects.
- **GitHub Discussions** — questions, usage feedback, and design discussion.

Feedback channels are asynchronous. The project does not use Discord, Slack, or live calls for feedback.

## What to include

Include the following in every report:

- Operating system and architecture.
- Output of `./ztd version`.
- The exact step or command that was run.
- Expected result.
- Actual result, including any error output.

Reports that describe a sequence of steps with expected and actual results are the most actionable.

Report the following categories:

- Setup or enrollment steps that fail or are unclear.
- Behavior on Operators running on an OS or architecture other than the one used for development.
- Documentation that does not match the binary's behavior. Treat a mismatch as a bug.

## Response expectations

- The maintainer reads and replies to feedback in batches, roughly twice a week.
- No response-time SLA applies.
